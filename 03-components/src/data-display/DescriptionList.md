# DescriptionList

**`@smego/ui`** · ชั้น 03 · [DescriptionList.tsx](./DescriptionList.tsx)

## 1 · ภาพรวม

คู่ชื่อ/ค่าระดับหน้า — ข้อมูลภาษีของผู้ขาย · รายละเอียดคำสั่งซื้อ · เงื่อนไขโครงการ · ข้อมูลติดต่อ

เป็น `<dl>` จริง ไม่ใช่ `<div>` สองอัน เพราะ screen reader ต้องประกาศความสัมพันธ์เป็นคู่ — *"เลขทะเบียนนิติบุคคล, 0105558012345"* ไม่ใช่สองก้อนที่ลอยอยู่ข้างกัน

### ★★ ต่างจาก `EntityMeta` ที่ขอบเขต ไม่ใช่ที่หน้าตา

ทั้งคู่เป็น `<dl>` และรับ `{ label, value }[]` เหมือนกัน — ความต่างคือที่อยู่

| | `EntityMeta` | `DescriptionList` |
|---|---|---|
| อยู่ที่ไหน | **ในการ์ด** | **ในหน้าหรือบล็อก** |
| ขนาดตัวอักษร | `text-caption` (13px) | `text-body-sm` (14px) |
| ข้อจำกัดความกว้าง | ต้องอ่านออกที่ **136px** | มีที่ให้หายใจ |
| จำนวนรายการที่เหมาะ | 1–3 | 3–12 |

**ห้ามใช้สลับกัน** — `DescriptionList` ในการ์ดจะดันการ์ดสูงจนกริดเสียจังหวะ · `EntityMeta` ในหน้าจะเล็กจนอ่านยากบนเดสก์ท็อป

### ❌ เมื่อไรที่ไม่ควรใช้

| สถานการณ์ | ใช้อะไรแทน | เหตุผล |
|---|---|---|
| ข้อมูลย่อในการ์ด | `<EntityMeta>` | ดูตารางด้านบน |
| เปรียบเทียบหลายรายการ | `<CompareTable>` | ต้องเห็นค่าของแต่ละเจ้าเรียงกัน |
| ข้อมูลที่แก้ไขได้ | `<TextInput>` ในฟอร์ม | `<dl>` เป็นข้อมูลอ่านอย่างเดียว |
| รายการที่ไม่มีชื่อกำกับ | `<ul>` | `<dt>` ว่างไม่ถูกต้องตาม HTML |
| ข้อมูลที่มีลำดับขั้น | `<OrderTimeline>` | คู่ชื่อ/ค่าไม่สื่อลำดับเวลา |

## 2 · React API

```tsx
import { DescriptionList } from '@smego/ui';

<DescriptionList
  layout="inline"
  items={[
    { label: 'เลขทะเบียนนิติบุคคล', value: '0105558012345', numeric: true },
    { label: 'สถานะภาษีมูลค่าเพิ่ม', value: 'จดทะเบียนแล้ว' },
    { label: 'หน่วยงานที่รับรอง', value: 'กรมพัฒนาธุรกิจการค้า (DBD)' },
  ]}
/>
```

| prop | type | ค่าเริ่มต้น | หมายเหตุ |
|---|---|---|---|
| `items` | `DescriptionListItem[]` | — | **บังคับ** · ว่างแล้วไม่ render อะไรเลย |
| `layout` | `'stacked' \| 'inline'` | `'stacked'` | `inline` ยุบเป็น stacked ใต้ `md` |
| `divided` | `boolean` | `false` | เส้นคั่นระหว่างรายการ |

### `DescriptionListItem`

| field | type | หมายเหตุ |
|---|---|---|
| `label` | `string` | **ต้องไม่ว่าง** — ดู §5 |
| `value` | `ReactNode` | รับ `<Badge>` · `<Link>` ได้ |
| `numeric` | `boolean` | `true` → `font-numeric` · ใช้กับเลขทะเบียน เลขผู้เสียภาษี จำนวนเงิน |

**ทางหนี:** ไม่มีและไม่จำเป็น — `<dl>` เป็น HTML ล้วน ไม่มี behavior ให้ทะลุ

## 3 · Variants

### layout — วัดจาก computed style

| layout | ที่ 1280px | ที่ 320px |
|---|---|---|
| `stacked` | ชื่อเหนือค่า · **1 คอลัมน์** | เหมือนกัน |
| `inline` | ชื่อซ้าย ค่าขวา · **2 คอลัมน์** (`minmax(0,12rem) minmax(0,1fr)`) | ★ ยุบเป็น **1 คอลัมน์** |

**★ ทำไม `inline` ต้องยุบ** — คู่ชื่อ/ค่า 2 คอลัมน์ที่ 320px ทำให้คอลัมน์ค่ากว้างไม่พอสำหรับเลข 13 หลักหรือชื่อหน่วยงานยาว ๆ · วัดที่ 320px ยืนยันว่า `dd.scrollWidth ≤ dd.clientWidth` — ไม่มีอะไรถูกตัด (A2)

`inline` ใช้ `grid-template-columns: subgrid` ที่ระดับแถว เพื่อให้ค่าทุกแถวเริ่มตรงแนวเดียวกัน — ไม่ใช่แต่ละแถวจัดเอง

### ความคมชัด — วัดจริงทั้ง 2 โหมด

| ส่วน | token | สว่าง | มืด |
|---|---|---|---|
| `<dt>` ชื่อ | `text-fg-muted` | **5.74:1** | **7.27:1** |
| `<dd>` ค่า | `text-fg` | **15.33:1** | **16.56:1** |

`<dt>` ใช้ `fg-muted` โดยตั้งใจ — ชื่อเป็นบริบท ค่าคือสิ่งที่ผู้ใช้มาหา ความต่างของน้ำหนักช่วยกวาดตา · ทั้งคู่ยังผ่าน 4.5:1

## 4 · States

| state | เกิดเมื่อ | สิ่งที่เปลี่ยน |
|---|---|---|
| **default** | มี `items` ≥ 1 | render `<dl>` |
| **empty** | `items.length === 0` | ★ **`return null`** — ไม่ปล่อย `<dl>` เปล่า |
| **hover / focus / active / disabled / loading / error** | — | ★ **ไม่มี** — เป็นการแสดงผลล้วน ไม่โต้ตอบ ไม่รับ focus |

> ★ การประกาศว่าไม่มี state คือข้อกำหนด ไม่ใช่การเว้นว่าง (`DESIGN-PRINCIPLES` A4(ก)) · ถ้า `value` ต้องมีสถานะโหลด ให้ผู้เรียกส่ง `<Skeleton>` เข้ามาเป็น `value`

`<dl>` เปล่าไม่มีความหมายทางความหมาย และปล่อยกล่องว่างไว้กินที่ — พฤติกรรมเดียวกับ `EntityMeta` และ `CompareBar` (`Compare.md §9`: *"แถบเปล่าเมื่อไม่มีรายการ → `return null`"*)

## 5 · Accessibility

| หัวข้อ | รายละเอียด |
|---|---|
| โครงสร้าง | `<dl>` → `<div>` → `<dt>` + `<dd>` · `<div>` ห่อคู่เป็นรูปแบบที่ HTML อนุญาต |
| ★ `<dt>` ห้ามว่าง | `<dt>` ว่างไม่ถูกต้องตาม HTML และทำให้ SR ประกาศคู่ที่ไม่มีชื่อ |
| SC 1.3.1 | ✅ ความสัมพันธ์ชื่อ/ค่าอยู่ใน markup ไม่ใช่แค่ในตำแหน่งบนจอ |
| SC 1.4.10 | ✅ ยุบเป็นคอลัมน์เดียวที่ 320px · ไม่มี horizontal scroll |
| SC 1.4.12 | ✅ ไม่ตั้ง `letter-spacing` · `line-height` มาจาก type scale |
| keyboard | ไม่มี focusable ในตัว component — ถ้า `value` เป็น `<Link>` มันได้ focus ตามปกติ |

### ★ ค่าที่อธิบายตัวเองได้ ให้อยู่นอก `<dl>`

กฎเดียวกับ `EntityMeta` (`EntityCard.tsx`) — ข้อความอย่าง *"ผู้ผลิต: บจก. ไทยโรสเตอร์"* ที่มีคำว่า "ผู้ผลิต" อยู่ในค่าแล้ว ไม่ควรบีบเข้า `<dl>` โดยปล่อย `<dt>` ว่าง · วางเป็น `<p>` นอก `<dl>` แทน

> **📌 หนี้เอกสารที่แก้พร้อมกัน** — `EntityCard.md:59` เคยเขียนว่า `EntityMeta` items `label` **ว่างได้** ซึ่งขัดกับ `EntityCard.tsx:229–234` ที่เขียนว่า **ต้องไม่ว่าง** พร้อมเหตุผล HTML
>
> **TSX ถูก** — แก้ `.md` ตามโค้ดแล้วในรอบเดียวกับที่สร้างไฟล์นี้

## 6 · Tailwind implementation

- **`grid` ไม่ใช่ `table`** — ตารางบังคับให้ทุกแถวสูงเท่ากันและยุบตามจอไม่ได้โดยไม่เสีย semantic (บทเรียนจาก `Compare.md §5` ที่ Safari/VoiceOver ทิ้ง semantic เมื่อ `display` ไม่ใช่ `table`) · `<dl>` + grid ไม่มีปัญหานี้เพราะ `<dl>` ไม่มี display-dependent semantic
- **`md:grid-cols-subgrid`** ที่ระดับแถว — ทำให้คอลัมน์ค่าของทุกแถวตรงแนวกันโดยไม่ต้องกำหนดความกว้างตายตัว
- **`minmax(0, …)` ทั้งสองคอลัมน์** — ลูกของ grid มี `min-width: auto` เป็นค่าเริ่มต้น จึงไม่ยอมย่อและดัน body ให้เลื่อนแนวนอน (`STYLE-GUIDELINE §5.4`)
- **`min-w-0` บน `<dd>`** ด้วยเหตุผลเดียวกัน
- **`font-numeric` เป็น opt-in ต่อรายการ** ไม่ใช่ทั้งลิสต์ — ชื่อหน่วยงานที่ได้ `tabular-nums` จะดูช่องไฟแปลก

## 7 · Figma Variant

Component set `DescriptionList`

| property | values |
|---|---|
| `Layout` | `stacked` · `inline` |

## 8 · Usage

```tsx
/* ข้อมูลภาษีของผู้ขาย — เหตุผลหลักที่ component นี้มีอยู่ */
<DescriptionList
  layout="inline"
  divided
  items={[
    { label: s.seller.registrationNumber, value: '0105558012345', numeric: true },
    { label: 'เลขประจำตัวผู้เสียภาษี', value: '0105558012345', numeric: true },
    {
      label: 'สถานะภาษีมูลค่าเพิ่ม',
      value: <Badge variant="success" label="จดทะเบียนแล้ว" />,
    },
    { label: 'ออกใบกำกับภาษีอิเล็กทรอนิกส์', value: 'ได้' },
    { label: 'หน่วยงานที่รับรอง', value: 'กรมพัฒนาธุรกิจการค้า (DBD)' },
  ]}
/>

/* ค่าที่ยังโหลดไม่เสร็จ — ผู้เรียกส่ง Skeleton เข้ามาเป็น value */
<DescriptionList
  items={[
    { label: 'ยอดสั่งซื้อสะสม', value: <Skeleton lines="body-sm" width="8rem" /> },
  ]}
/>
```

## 9 · Anti-patterns

| ❌ | ✅ | ทำไม |
|---|---|---|
| `label: ''` เมื่อค่าอธิบายตัวเอง | วางเป็น `<p>` นอก `<dl>` | `<dt>` ว่างไม่ถูกตาม HTML · SR ประกาศคู่ที่ไม่มีชื่อ |
| ใช้ `<div>` + `<span>` แทน `<dl>` | `<dl>` | SR ประกาศ "ชื่อ, ค่า" เป็นคู่ ไม่ใช่สองก้อนแยกกัน |
| ใช้ในการ์ดแทน `<EntityMeta>` | `<EntityMeta>` | 14px ในการ์ดดันความสูงจนกริดเสียจังหวะ |
| `inline` ที่ไม่ยุบใต้ md | ยุบเป็น 1 คอลัมน์ | เลข 13 หลักไม่มีที่พอในคอลัมน์ค่าที่ 320px |
| `font-numeric` ทั้งลิสต์ | opt-in ต่อรายการ | ชื่อหน่วยงานที่ได้ `tabular-nums` ช่องไฟดูแปลก |
| render `<dl>` เปล่าเมื่อไม่มีข้อมูล | `return null` | กล่องว่างกินที่โดยไม่ให้อะไร (เหมือน `Compare.md §9`) |
| ใส่ปุ่มแก้ไขใน `<dd>` ทุกแถว | ปุ่มเดียวเหนือลิสต์ | `<dl>` เป็นข้อมูลอ่านอย่างเดียว · ปุ่มรายแถวทำให้ tab order ยาวโดยไม่จำเป็น |
| คอลัมน์ไม่มี `minmax(0, …)` | มี | ลูกของ grid ไม่ยอมย่อ → body เลื่อนแนวนอน (SC 1.4.10) |
