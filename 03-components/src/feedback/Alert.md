# Alert

**`@smego/ui`** · ชั้น 03 · [Alert.tsx](./Alert.tsx)

---

## 1 · ภาพรวม

ข้อความที่ **อยู่ค้างจนผู้ใช้จัดการ** — ไม่หายเอง ไม่มีตัวจับเวลา

Alert คือ component ที่ **รักษากฎ "ไม่มีอะไรหายไปตามเวลา"** ซึ่งระบบนี้ประกาศไว้สามที่แล้ว (Tooltip SC 1.4.13 · นับถอยหลัง QR SC 2.2.1 · เหตุผลที่แบน native validation) · `Toast` คือข้อยกเว้นที่ถูกจำกัดขอบเขตไว้แคบ

**เส้นแบ่งที่บังคับใช้จริง: error ใช้ Alert ห้ามใช้ Toast**

### ❌ เมื่อไรที่ไม่ควรใช้

| สถานการณ์ | ใช้อะไรแทน | เหตุผล |
|---|---|---|
| ยืนยันซ้ำสิ่งที่ผู้ใช้เห็นผลอยู่แล้ว | `<Toast>` | ถ้าผู้ใช้เห็นรายการหายไปจากตะกร้าแล้ว กล่องค้างเป็นการขอให้ปิดเพิ่มอีกงาน |
| คำอธิบายวิธีกรอกช่อง | `description` ของ field | Alert แยกจากช่องกรอก ผู้ใช้ SR อ่านไม่เจอตอนอยู่ในช่อง |
| error ของช่องกรอกช่องเดียว | `errorMessage` ของ field | RAC ต่อ `aria-describedby` ให้แล้ว · Alert แยกทำให้ผู้ใช้ต้องหาว่าช่องไหน |
| ของที่ลอยทับเนื้อหา | `<Dialog>` | Alert อยู่ในกระแสของหน้า ไม่ขัดจังหวะ |
| สถานะของ entity เช่น "ใกล้ปิดรับ" | `<DeadlineBadge>` / `<Badge>` | สถานะติดกับของ ไม่ใช่ประกาศระดับหน้า |

**ใช้ Alert ระดับฟอร์ม** เมื่อ error มาจาก server หรือครอบหลายช่อง (`"บันทึกไม่สำเร็จ"`) — ไม่ใช่แทน `errorMessage` ของแต่ละช่อง แต่ใช้**เพิ่ม**จากนั้น

## 2 · React API

```tsx
import { Alert } from '@smego/ui';

<Alert tone="danger" isLive title="บันทึกไม่สำเร็จ">
  เชื่อมต่อไม่ได้ — ตรวจสอบสัญญาณอินเทอร์เน็ตแล้วลองอีกครั้ง
</Alert>
```

| prop | type | ค่าเริ่มต้น | หมายเหตุ |
|---|---|---|---|
| `title` | `string` | — | **บังคับ** · บอกสิ่งที่เกิดขึ้น ไม่ใช่ระดับความรุนแรง |
| `children` | `ReactNode` | — | รายละเอียด · error ตามสูตร **ทำไม → แก้อย่างไร** |
| `tone` | `'info' \| 'success' \| 'warning' \| 'danger'` | `'info'` | |
| `isLive` | `boolean` | **`false`** | ⚠️ ดู §5 — ค่าเริ่มต้นเป็น `false` โดยตั้งใจ |
| `action` | `ReactNode` | — | ปุ่ม · ซ้อนแนวตั้งบนมือถือ |
| `onDismiss` | `() => void` | — | ⚠️ ผู้เรียกต้องคืน focus เอง |
| `titleAs` | `'h2' \| 'h3' \| 'h4'` | **ไม่เป็นหัวข้อ** | ดู §5 |
| `className` | `string` | — | |

**ไม่มี prop `icon`** — ไอคอนถูกล็อกกับ `tone` เพราะรูปทรงคือสิ่งที่ทำให้ผ่าน SC 1.4.1 การให้เปลี่ยนได้เท่ากับให้ปิดกลไกนั้น

**ไม่มี prop `autoDismissMs`** — นั่นคือ `Toast`

### ทางหนีเมื่อ wrapper ไม่พอ

```tsx
import { alertStyles } from '@smego/ui';
<section className={alertStyles({ tone: 'warning' })}>…</section>
```

## 3 · Variants

| tone | ไอคอน (รูปทรง) | พื้น | ขอบ | ใช้เมื่อไร |
|---|---|---|---|---|
| `info` | `info` — วงกลม + i | `info-surface` | `info-edge` | เงื่อนไข กำหนดเวลา ข้อมูลที่ต้องรู้ก่อนกรอก |
| `success` | `circle-check` — วงกลม + ถูก | `success-surface` | `success-edge` | ผลลัพธ์ที่ผู้ใช้ต้องอ่านให้จบ เช่นเลขที่คำสั่งซื้อ |
| `warning` | `triangle-alert` — **สามเหลี่ยม** | `warning-surface` | `warning-edge` | เรื่องที่เปลี่ยนการตัดสินใจ แต่ยังทำต่อได้ |
| `danger` | `circle-x` — วงกลม + กากบาท | `danger-surface` | `danger-edge` | ทำต่อไม่ได้จนกว่าจะแก้ |

### ★★ ไอคอน 4 ตัว **รูปทรงต่างกันจริง** ไม่ใช่ตัวเดียวเปลี่ยนสี

ข้อนี้สำคัญกับ SME.GO เป็นพิเศษ: **ทองกับเหลืองห่างกันแค่ 12°** (ข้อ 02 การตัดสินใจ 6) ผู้ใช้ที่แยกเหลืองจากส้มไม่ได้ต้องอ่านออกจากรูปทรง

**เทสจริง:** เทียบ `svg.innerHTML` ของทั้ง 4 tone → ได้ 4 ค่าที่ไม่ซ้ำกัน

### ★ `warning` ≠ `danger` — เกณฑ์คือ "ทำต่อได้ไหม"

`warning` = ทำต่อได้แต่ควรรู้ (ผู้ขายไม่จด VAT) · `danger` = ทำต่อไม่ได้ (บันทึกไม่สำเร็จ) · ถ้าเลือกไม่ถูก ผู้ใช้จะเรียนรู้ว่าสีแดงไม่ได้หมายความว่าต้องทำอะไร แล้วเลิกอ่านทั้งสองแบบ

## 4 · States

Alert ไม่มี interactive state ของตัวเอง — state อยู่ที่ปุ่มปิดและปุ่มใน `action`

| state | ที่มา |
|---|---|
| ปุ่มปิด hover | `IconButton variant="ghost"` → `bg-sunken` |
| ปุ่มปิด focus-visible | วงแหวน 2 ชั้นจาก `base.css` |
| ประกาศแล้ว | `isLive` → `role="alert"` / `"status"` (ไม่มีสัญญาณทางสายตา) |

## 5 · Accessibility

| เรื่อง | ข้อกำหนด |
|---|---|
| role | **ไม่มีโดยค่าเริ่มต้น** · `isLive` → `alert` (danger/warning) หรือ `status` (info/success) |
| **SC 4.1.3** | `isLive` สำหรับ Alert ที่โผล่มาตอบการกระทำ |
| **SC 1.4.1** | ไอคอน 4 รูปทรง ไม่ใช่แค่สี |
| **SC 2.5.3** | ชื่อปุ่มปิดรวม `title` |
| **SC 2.5.8** | ปุ่มปิด `size="md"` → เป้า **36×36** |
| **SC 2.2.1** | ไม่มีตัวจับเวลา — Alert ไม่หายเอง |
| หัวข้อ | `title` **ไม่เป็นหัวข้อ** โดยค่าเริ่มต้น |

### ★★★ `role="alert"` ไม่ใช่ค่าเริ่มต้น — และนี่คือการตัดสินใจ

Alert ส่วนใหญ่ถูก render มาพร้อมหน้า (แจ้งกำหนดปิดรับ · แจ้งว่าผู้ขายไม่จด VAT) · `role="alert"` บน element ที่มีอยู่ตั้งแต่ตอนโหลด ทำให้ screen reader บางคู่ประกาศข้อความนั้น **แทรกก่อนชื่อหน้า** ผู้ใช้จึงได้ยินข้อความลอย ๆ โดยไม่รู้ว่าอยู่หน้าอะไร

```tsx
{/* ✅ มาพร้อมหน้า — ไม่ประกาศ อ่านตามลำดับเอกสาร */}
<Alert tone="info" title="ปิดรับสมัครวันที่ 30 กันยายน 2569" />

{/* ✅ โผล่มาตอบการกด "บันทึก" — ประกาศทันที (SC 4.1.3) */}
{saveError && <Alert isLive tone="danger" title="บันทึกไม่สำเร็จ">…</Alert>}
```

**เทสจริง:** ค่าเริ่มต้นไม่มีทั้ง `[role=alert]` และ `[role=status]` ใน DOM

### ★★ `assertive` แค่กับ tone ที่ขัดจังหวะแล้วสมเหตุสมผล

`danger` และ `warning` → `role="alert"` (assertive · ตัดสิ่งที่กำลังอ่านอยู่) · `info` และ `success` → `role="status"` (polite · รอจบประโยค)

"บันทึกสำเร็จ" ที่ตัดกลางประโยคที่ผู้ใช้กำลังฟังคือการรบกวนโดยไม่จำเป็น

### ★★ `title` ไม่เป็นหัวข้อโดยค่าเริ่มต้น

หน้าที่มี 3 Alert จะได้ 3 หัวข้อปน `<h2>`/`<h3>` ของเนื้อหาจริง ทำให้ผู้ใช้ที่เลื่อนดูตามหัวข้อ (วิธีสำรวจหน้าที่ใช้มากที่สุดวิธีหนึ่ง) เจอโครงที่อ่านไม่ออก · ตั้ง `titleAs` เฉพาะเมื่อ Alert **เป็นหัวของส่วนเนื้อหาจริง** ไม่ใช่เพื่อให้ตัวอักษรหนาขึ้น

### ★★★ กดปิดแล้ว focus หลุดไป `<body>` — ผู้เรียกต้องคืน

เมื่อกดปิด element ที่ถือ focus หายจาก DOM ผู้ใช้คีย์บอร์ดจึงกลับไปต้นหน้า · component รู้ไม่ได้ว่าควรคืน focus ไปไหน

```tsx
{error && (
  <Alert
    isLive tone="danger" title="บันทึกไม่สำเร็จ"
    onDismiss={() => {
      setError(null);
      /* คืน focus ไปที่ปุ่มที่ทำให้ Alert โผล่มา */
      document.getElementById('save-seller')?.focus();
    }}
  />
)}
<Button id="save-seller" onPress={save}>บันทึกข้อมูลผู้ขาย</Button>
```

⚠️ ใช้ `id` ไม่ใช่ `ref` เพราะ **`<Button>` ไม่ได้ forwardRef** — `ref` จะทะลุถึง RAC เฉพาะบน React 19 ที่ `ref` เป็น prop ธรรมดา แต่ `peerDependencies` ของ package เปิดถึง React 18 ซึ่งจะทิ้ง `ref` เงียบ ๆ

**และนี่คือเหตุผลที่ Alert ที่บอกว่าต้องแก้อะไร ไม่ควรปิดได้เลย** — ปิดไปแล้วผู้ใช้ไม่มีทางเรียกกลับมาอ่าน

### ★★ ตัวเลข contrast ที่วัดจริง

พื้น tint ของแต่ละ tone · `text-fg` / `text-fg-secondary` / ไอคอน:

| tone | สว่าง | มืด |
|---|---|---|
| `info` | 15.14 / 8.08 / 6.15 | 13.72 / 9.78 / 5.95 |
| `success` | 15.29 / 8.16 / 5.65 | 13.77 / 9.82 / 7.30 |
| `warning` | 15.59 / 8.32 / **5.35** | 11.90 / 8.49 / 8.80 |
| `danger` | 14.66 / 7.83 / 5.42 | 15.48 / 11.04 / 5.53 |

ผ่าน AA ทั้ง 24 ค่า · ค่าต่ำสุดคือไอคอน `warning` ที่ **5.35**

### ★★ กล่องแทบมองไม่เห็นในโหมดสว่าง — และยอมรับได้

พื้น tint เทียบ canvas ได้แค่ **1.00–1.05** (`warning` 1.02) และขอบ `--color-*-edge` ได้ **1.27–1.99** · กล่องจึงอ่านเป็นย่อหน้าที่มีไอคอน มากกว่าเป็นกล่อง

**ไม่ใช่บั๊ก** — ตัวเลขนี้อยู่ในย่านเดียวกับ `--color-edge` (1.56) และ `--color-edge-subtle` (1.27) ที่ระบบประกาศเองว่าเป็น**ขอบตกแต่ง** และ `Card` ตอนพักก็ใช้ค่านั้น · Alert ไม่ใช่ control จึงไม่อยู่ในขอบเขต SC 1.4.11 และความหมายมาจากไอคอน + ข้อความตาม SC 1.4.1 อยู่แล้ว

⚠️ **ผลที่ตามมา: ห้ามพึ่งกล่องเป็นตัวสื่อความรุนแรง** — `title` ต้องบอกสิ่งที่เกิดขึ้นด้วยตัวเอง

### ★ ไม่มีข้อความใหม่ในระบบ

Alert ใช้ `s.common.close` ที่มีอยู่แล้วตัวเดียว — `title` และรายละเอียดมาจากผู้เรียกทั้งหมด เพราะเป็นข้อความของโดเมน ไม่ใช่ของ component (ข้อ 26)

## 6 · Tailwind implementation

```ts
const alertStyles = cva(
  [
    'grid min-w-0 gap-2',
    'rounded-(--radius-container) border',
    'p-3 md:p-4',
    /* ★ ข้อความเป็น text-fg ทุก tone — สีสถานะอยู่ที่ไอคอนกับขอบ */
    'text-fg',
  ],
  {
    variants: {
      tone: {
        info:    'bg-info-surface border-info-edge',
        success: 'bg-success-surface border-success-edge',
        warning: 'bg-warning-surface border-warning-edge',
        danger:  'bg-danger-surface border-danger-edge',
      },
    },
    defaultVariants: { tone: 'info' },
  },
);
```

### ★★ ข้อความเป็น `text-fg` ไม่ใช่สีตามสถานะ

**ไม่มี `--color-warning-fg` ในระบบโดยตั้งใจ** — yellow ทุกขั้นที่อ่านได้บนพื้นสว่างเข้มเกินกว่าจะต่างจาก `text-fg` อย่างมีความหมาย และ `warning-500` ได้ **1.66:1** ซึ่งใช้เป็นข้อความไม่ได้เลย (ข้อ 02)

สีสถานะจึงอยู่ที่ **ไอคอนกับขอบ** เท่านั้น

### ★ ปุ่มใน `action` ซ้อนแนวตั้งบนมือถือ

```tsx
'flex flex-col-reverse gap-2 ps-8 sm:flex-row sm:items-center'
```

`flex-col-reverse` เพราะการกระทำหลักอยู่ท้าย DOM (ลำดับที่ถูกสำหรับคีย์บอร์ด) แต่ต้องอยู่บนสุดที่จอแคบ (ข้อ 08 §7) · `ps-8` ให้ปุ่มตรงกับข้อความ ไม่ตรงกับไอคอน

## 7 · Figma Variant

Component set **`Alert`**

| Property | Values |
|---|---|
| `Tone` | `Info` · `Success` · `Warning` · `Danger` |
| `Dismissible` | `True` · `False` |
| `HasAction` | `True` · `False` |
| `HasDescription` | `True` · `False` |

**ไอคอนต้องผูกกับ `Tone` เป็น 4 รูปทรงต่างกัน** — ถ้า Figma ใช้ไอคอนเดียวเปลี่ยนสี นักพัฒนาจะทำตามและตก SC 1.4.1

**ห้ามมี property `Live` ใน Figma** — เป็นพฤติกรรม ไม่ใช่หน้าตา ใส่ไว้จะทำให้นักออกแบบคิดว่ามีอะไรให้เห็น · เขียนไว้ใน description ของ component แทน

**frame ตัวอย่างต้องมีข้อความไทย 2–3 บรรทัด** ไม่ใช่บรรทัดเดียว — ข้อความไทยยาวกว่าอังกฤษ 20–40% และ error ตามสูตร "ทำไม → แก้อย่างไร" ยาวเสมอ

## 8 · Usage

```tsx
// ★ มาพร้อมหน้า — ไม่ประกาศ
<Alert tone="info" title="ปิดรับสมัครวันที่ 30 กันยายน 2569">
  ระบบจะปิดรับเอกสารเวลา 16.30 น. ของวันดังกล่าว เอกสารที่ส่งหลังจากนั้นจะไม่ถูกพิจารณา
</Alert>
```

```tsx
// ★ error จาก server — ประกาศทันที + มีทางออก
{saveError && (
  <Alert
    isLive
    tone="danger"
    title="บันทึกไม่สำเร็จ"
    action={<Button onPress={retry}>ลองบันทึกอีกครั้ง</Button>}
  >
    เชื่อมต่อไม่ได้ — ตรวจสอบสัญญาณอินเทอร์เน็ตแล้วลองอีกครั้ง ข้อมูลที่กรอกไว้ยังอยู่
  </Alert>
)}
```

```tsx
// ★ warning ที่เปลี่ยนการตัดสินใจ — ปิดไม่ได้โดยตั้งใจ
<Alert tone="warning" title="ผู้ขายรายนี้ไม่ได้จดทะเบียนภาษีมูลค่าเพิ่ม">
  ผู้ซื้อจะขอคืนภาษีซื้อไม่ได้ ต้นทุนจริงจึงต่างจากราคาที่แสดงประมาณ 7%
</Alert>
```

```tsx
// ★ success ที่ต้องอ่านให้จบ — เลขที่คำสั่งซื้อคัดลอกได้
<Alert isLive tone="success" title="ส่งคำสั่งซื้อแล้ว">
  เลขที่คำสั่งซื้อ <span className="select-all font-numeric">PO-2569-004182</span>{' '}
  ผู้ขายจะยืนยันภายใน 2 วันทำการ
</Alert>
```

## 9 · Anti-patterns

| ❌ | ✅ | ทำไม |
|---|---|---|
| `<Toast>` สำหรับ error | `<Alert isLive tone="danger">` | ข้อความที่บอกว่าต้องทำอะไรต่อ ห้ามหายก่อนอ่านจบ (grill 2026-07-26 ข้อ 4) |
| `isLive` กับ Alert ทุกตัว | `isLive` เฉพาะตัวที่โผล่มาตอบการกด | `role="alert"` ตอนโหลดหน้าแทรกก่อนชื่อหน้า |
| `title="ข้อผิดพลาด"` | `title="บันทึกไม่สำเร็จ"` | บอกระดับความรุนแรงไม่ช่วยอะไร ผู้ใช้ต้องรู้ว่าอะไรเกิดขึ้น (ข้อ 01 §1.2) |
| `titleAs="h3"` ทุกตัวเพื่อให้หนา | ไม่ตั้ง `titleAs` | ปนโครงหัวข้อของหน้า · `text-label` หนาอยู่แล้ว |
| `onDismiss` กับ Alert ที่บอกว่าต้องแก้ | ไม่ให้ปิด | ปิดแล้วผู้ใช้เรียกกลับมาอ่านไม่ได้ |
| `onDismiss={() => setError(null)}` เฉย ๆ | คืน focus ด้วย | focus ตกไป `<body>` ผู้ใช้คีย์บอร์ดกลับต้นหน้า |
| `action` เป็นทางเดียวที่ทำสิ่งนั้นได้ + ปิดได้ | ให้มีทางอื่นเสมอ | ปิดไปแล้วทางนั้นหายไปด้วย |
| `<Alert>` แทน `errorMessage` ของ field | ใช้ทั้งสอง | Alert ระดับฟอร์มไม่บอกว่าช่องไหน · RAC ต่อ `aria-describedby` ให้ที่ field แล้ว |
| `tone="danger"` กับเรื่องที่ทำต่อได้ | `tone="warning"` | ถ้าแดงไม่ได้หมายความว่าต้องทำอะไร ผู้ใช้เลิกอ่านทั้งสองแบบ |
| ไอคอนเดียวเปลี่ยนสี 4 tone | 4 รูปทรง | SC 1.4.1 · ทองกับเหลืองห่างแค่ 12° |
| `text-danger-icon` เป็นสีข้อความในกล่อง | `text-fg` | ไม่มี `--color-warning-fg` และสีสถานะเป็นข้อความยาวอ่านล้า |
| พึ่งกล่องสีเป็นตัวสื่อความรุนแรง | `title` บอกด้วยตัวเอง | พื้น tint เทียบ canvas ได้ 1.00–1.05 |
