# ProgressBar

**`@smego/ui`** · ชั้น 03 · [ProgressBar.tsx](./ProgressBar.tsx)

---

## 1 · ภาพรวม

แถบความคืบหน้าของงานที่ **รู้ค่า** — โควตาทุนที่จัดสรรไปแล้ว · ความคืบหน้าการอัปโหลด · ที่นั่งที่ถูกจอง · ขั้นที่ทำเสร็จจากทั้งหมด

**กฎข้อแรกที่ตัดสินทุกอย่างที่เหลือ: ตัวเลขบังคับ แถบเป็นของแถม** — ไม่มี prop `hideValue` และจะไม่มี · แถบสีอย่างเดียวไม่ผ่าน SC 1.4.1 และผู้ใช้ที่มองเห็นก็อ่าน "ประมาณสามในสี่" ไม่ได้แม่นเท่า `780 / 1,000 ล้านบาท`

### ❌ เมื่อไรที่ไม่ควรใช้

| สถานการณ์ | ใช้อะไรแทน | เหตุผล |
|---|---|---|
| ไม่รู้ว่างานจะเสร็จเมื่อไร | `<Skeleton>` | **component นี้ไม่มีโหมด indeterminate** — ดูด้านล่าง |
| **ยอดเงินที่ผู้ใช้จะได้รับ** | `<EntityAmount>` | ★★ แถบทำให้ตัวเลขดูเหมือนเงินที่กำลังไหลเข้ามา |
| ขั้นตอนที่มีชื่อ เช่นฟอร์ม 4 ขั้น | `<CheckoutStepper>` · `<OrderTimeline>` | ผู้ใช้ต้องรู้ว่าขั้นถัดไปคืออะไร ไม่ใช่แค่ "เหลืออีก 25%" |
| การให้คะแนน 4.2 จาก 5 | `<Badge>` + ข้อความ | คะแนนไม่ใช่ความคืบหน้า ไม่มีอะไรกำลังเดินหน้า |

### ⚠️ ไม่มีโหมด indeterminate — เป็นการตัดสินใจ ไม่ใช่การละเว้น

แถบที่วิ่งไปมาโดยไม่มีตัวเลขขัดกฎข้อแรกของ component นี้โดยตรง และ `Skeleton.md §1` ครอบคลุมกรณี "ไม่รู้ว่าจะได้อะไรมา" ไว้แล้ว

`value={null}` ที่รองรับอยู่ **ไม่ใช่ indeterminate** — มันคือ *"ยังไม่ทราบค่า"* ซึ่งแสดงเป็นข้อความ ไม่ใช่การเคลื่อนไหว

### ★★ ห้ามใช้กับยอดเงินที่ผู้ใช้จะได้รับ

`GrantCard.md §3` บันทึกไว้ว่าความผิดพลาดที่แพงที่สุดในระบบคือผู้ใช้อ่าน **"วงเงินสูงสุด"** เป็น **"เงินที่จะได้รับ"** — แถบที่ค่อย ๆ เต็มเร่งความเข้าใจผิดนั้นโดยตรง เพราะภาษาภาพของ progress bar คือ *"สิ่งนี้กำลังเดินหน้ามาหาคุณ"*

**ใช้ได้:** โควตาของทั้งโครงการที่ถูกจัดสรรไปแล้ว (ข้อมูลระดับโครงการ)
**ใช้ไม่ได้:** วงเงินที่ผู้ใช้คนนี้ขอได้ (ข้อมูลระดับบุคคล)

## 2 · React API

```tsx
import { ProgressBar } from '@smego/ui';

<ProgressBar
  label="วงเงินโครงการที่จัดสรรแล้ว"
  value={780}
  maxValue={1000}
  format="ratio"
  unit="ล้านบาท"
  note="ข้อมูล ณ 25 กรกฎาคม 2569"
/>
```

| prop | type | ค่าเริ่มต้น | หมายเหตุ |
|---|---|---|---|
| `label` | `string` | — | **บังคับ** — เป็นทั้ง label ที่เห็นและชื่อที่ SR ประกาศ |
| `value` | `number \| null` | — | **บังคับ** · `null` = ยังไม่ทราบ ไม่ใช่ 0 |
| `maxValue` | `number` | `100` | |
| `format` | `'percent' \| 'ratio'` | `'percent'` | `ratio` แสดงทั้งค่าและเพดาน |
| `unit` | `string` | — | ต่อท้ายเมื่อ `format="ratio"` |
| `note` | `ReactNode` | — | ที่มาของตัวเลข เช่นวันที่อัปเดต (ข้อ 01 §4.2) |
| `unknownLabel` | `string` | `s.progress.unknown` | ข้อความแทนตัวเลขเมื่อ `value` เป็น `null` |
| `size` | `'sm' \| 'md'` | `'md'` | |
| `tone` | `'brand' \| 'success' \| 'danger'` | `'brand'` | **ไม่มี `warning`** — ดู §3 |

**ทางหนี:** `@smego/ui/primitives` เปิด `ProgressBar` · `Label` ของ RAC ให้ตรง ๆ

## 3 · Variants

### tone × พื้นหลัง — วัดจาก computed style ใน browser จริง

| tone | token | แถบเทียบราง สว่าง | แถบเทียบราง มืด | ผล |
|---|---|---|---|---|
| `brand` | `bg-primary-600` | **4.28:1** | **3.86:1** | ✅ |
| `success` | `bg-success-fill` | **5.37:1** | **3.09:1** | ✅ |
| `danger` | `bg-danger-fill` | **5.37:1** | **3.09:1** | ✅ |

### ⚠️ ข้อจำกัดที่ค้นพบจากการวัด ไม่ใช่การออกแบบ — ไม่มี tone `warning`

`--color-warning-fill` (yellow-500) บนราง `sunken` ได้ **1.49:1** ในโหมดสว่าง ต่ำกว่าเกณฑ์ 3:1 อย่างมาก

นี่คืออาการเดียวกับที่ระบบเจอมาแล้ว 2 ครั้ง — ทองและเหลืองสว่างเกินกว่าจะเป็นพื้นทึบบนพื้นอ่อน (ข้อ 02 §9 "ทองไม่ใช่สถานะ" · `STYLE-GUIDELINE §8` "ทองกับเหลืองห่างกัน 1.43:1") · **ใช้ `danger` แทนเมื่อโควตาใกล้หมด**

### size

| size | class | ความสูงกล่อง | พื้นที่แถบจริง |
|---|---|---|---|
| `sm` | `h-2` | **8px** | 6px |
| `md` | `h-3` | **12px** | 10px |

> **📌 ค้นพบจากการวัด** — เดิมเอกสารฉบับร่างเขียนว่า md สูง **14px** (12 + ขอบ 1 × 2)
>
> **ผิด** · Tailwind v4 ตั้ง `box-sizing: border-box` เป็นค่าเริ่มต้น ขอบ 1px จึงกินเข้าไป**ใน** `h-3` ไม่ได้บวกออก — กล่องรวมได้ **12px** และพื้นที่แถบเหลือ **10px**
>
> ต่างจากกรณี `Button` ที่เอกสารเคยผิด **+2px** เพราะปุ่มสูงจาก padding ซึ่งขอบบวกออกจริง · บทเรียนเดียวกัน คนละทิศ — ยืนยันด้วยการวัดเสมอ (`tests/e2e/pass3.spec.ts`)

## 4 · States

| state | เกิดเมื่อ | สิ่งที่เปลี่ยน |
|---|---|---|
| **default** | `0 < value < maxValue` | แถบยาวตามสัดส่วน · ตัวเลขแสดงค่าจริง |
| **empty** | `value === 0` | แถบกว้าง 0 · **`aria-valuenow="0"`** · ตัวเลข `0%` |
| **complete** | `value === maxValue` | แถบเต็มราง |
| **unknown** | `value === null` | ★ **ไม่วาดแถบเลย** · ไม่มี `aria-valuenow` · แสดง `unknownLabel` |
| **overflow** | `value > maxValue` | แถบหนีบที่ 100% · **ตัวเลขยังแสดงค่าจริง** — ข้อมูลผิดของต้นทางต้องเห็น ไม่ใช่ถูกกลบ |
| **hover / focus / active / disabled** | — | ★ **ไม่มี** — ProgressBar ไม่โต้ตอบ ไม่รับ focus ไม่มี state เหล่านี้ |

> ★ การประกาศว่า *ไม่มี* 4 state สุดท้ายคือข้อกำหนด ไม่ใช่การเว้นว่าง — ตาม `DESIGN-PRINCIPLES` A4(ก) ที่ยกเว้นเฉพาะ component แสดงผลล้วนที่**ประกาศชัดเจน**

**★★ `value={0}` กับ `value={null}` ต้องแยกกันเด็ดขาด** — แถบว่างเปล่าอ่านว่า *"ยังไม่มีใครใช้โควตาเลย"* ซึ่งอาจตรงข้ามกับความจริง · `null` จึงไม่ประกาศ `aria-valuenow` เลย

## 5 · Accessibility

| หัวข้อ | รายละเอียด |
|---|---|
| role | `progressbar` — มาจาก RAC `ProgressBar` |
| ชื่อ | ★ ต้องใช้ **RAC `Label`** ไม่ใช่ `<span>` · RAC ต่อ `aria-labelledby` ให้เอง |
| `aria-valuetext` | ข้อความเดียวกับที่ตาเห็นเป๊ะ (SC 2.5.3) |
| `aria-valuenow` | ไม่ประกาศเมื่อ `value === null` |
| แถบ | `aria-hidden="true"` — ค่าอยู่ที่ `aria-valuetext` แล้ว ไม่ประกาศซ้ำ |
| SC 1.4.1 | ✅ ตัวเลขบังคับ — สีไม่ใช่ช่องทางเดียว |
| SC 1.4.11 | ✅ แถบเทียบราง ≥ 3:1 · ขอบรางเทียบพื้นหน้า ≥ 3:1 ทั้ง 2 โหมด |
| SC 1.4.10 | ✅ ไม่มี horizontal scroll ที่ 320px |
| reduced motion | `transition-[width]` ประกาศแบบ `motion-safe:` — ALLOW list ของ `base.css` ไม่รวม `width` จึงต้องประกาศเอง |

### ★★ โหมดมืด: ราง `sunken` = พื้น `canvas` เป๊ะ

| วัดได้ | สว่าง | มืด |
|---|---|---|
| ราง เทียบ พื้นหน้า | 1.06:1 | **1.00:1** |
| **ขอบราง** เทียบ พื้นหน้า | **3.99:1** | **4.38:1** |

`STYLE-GUIDELINE §5.4` บันทึกกับดักนี้ไว้แล้ว (*"`bg-sunken` ต้องอยู่บน `bg-surface` ห้ามอยู่บน `bg-canvas`"*) แต่ ProgressBar ต้องวางได้ทุกที่ **ขอบ `edge-strong` จึงเป็นข้อกำหนด ไม่ใช่การตกแต่ง** — ถ้าลบขอบออก รางจะหายทั้งเส้นในโหมดมืด และผู้ใช้เห็นแค่แถบสีลอย ๆ ที่ไม่รู้ว่าเทียบกับอะไร

มีเทสยืนยันข้อเท็จจริงนี้โดยตรง — ถ้าวันหนึ่ง token เปลี่ยนจนไม่จริงแล้ว เทสจะเตือน

### ความคมชัดของข้อความ — วัดจริง

| ส่วน | สว่าง | มืด |
|---|---|---|
| label (14px) | 8.19:1 | 11.81:1 |
| ตัวเลข (14px) | 15.33:1 | 16.56:1 |
| note (13px) | 5.74:1 | 7.27:1 |

## 6 · Tailwind implementation

- **CVA แยก 2 ชุด** — `trackStyles` (size) และ `fillStyles` (tone) เพราะรางกับแถบเปลี่ยนคนละมิติ การรวมเป็น object เดียวจะอ่านไม่ออกว่า class ไหนของส่วนไหน (`STYLE-GUIDELINE §5.2`)
- **ราง `overflow-hidden`** ปลอดภัยที่นี่ เพราะไม่มี focusable อยู่ข้างใน — ต่างจากข้อห้ามทั่วไปที่ตัดวงแหวน focus
- **ความกว้างแถบเป็น inline `style`** ไม่ใช่ class — เป็นค่าที่คำนวณตอน runtime จะทำเป็น arbitrary value ไม่ได้
- **`motion-safe:transition-[width]`** — บล็อก reduced motion ใน `base.css` คืน transition ให้เฉพาะ `opacity · color · background-color · border-color · box-shadow · fill · stroke · outline-color` · `width` ไม่อยู่ในนั้น จึงต้องประกาศเอง และต้องเป็น `motion-safe:` ไม่ใช่ประกาศลอย ๆ
- **`rounded-(--radius-control)`** ไม่ใช่ `rounded-full` — รางที่โค้งสุดจะทำให้แถบที่สั้นมาก (< 5%) ดูเป็นจุดกลม อ่านไม่ออกว่าเป็นแถบ

## 7 · Figma Variant

Component set `ProgressBar`

| property | values |
|---|---|
| `Size` | `sm` · `md` |
| `Tone` | `brand` · `success` · `danger` |
| `Value` | `0%` · `40%` · `78%` · `100%` · `unknown` |
| `Note` | `True` · `False` |

**ที่ห้ามลืม:** frame `unknown` ต้องมีจริง — ถ้ามีแต่แบบมีตัวเลข นักพัฒนาจะเดาว่า `null` แสดงเป็น 0% (เหตุผลเดียวกับ `Checkout.md §7` ที่บังคับให้มี frame `Mobile (text)`)

**ห้ามสร้าง:** variant `Warning` — ไม่มีในโค้ดและวัดแล้วไม่ผ่าน (§3)

## 8 · Usage

```tsx
/* โควตาโครงการ — ข้อมูลระดับโครงการ ใช้ได้ */
<ProgressBar
  label="วงเงินโครงการที่จัดสรรแล้ว"
  value={780}
  maxValue={1000}
  format="ratio"
  unit="ล้านบาท"
  note={s.progress.updatedAt('25 กรกฎาคม 2569')}
/>

/* โควตาใกล้หมด — ใช้ danger ไม่ใช่ warning */
<ProgressBar
  label="ที่นั่งที่ถูกจองแล้ว"
  value={38}
  maxValue={40}
  format="ratio"
  unit="ที่นั่ง"
  tone="danger"
/>

/* หน่วยงานยังไม่เปิดเผยยอดจัดสรร — ห้ามเดาเป็น 0 */
<ProgressBar
  label="วงเงินโครงการที่จัดสรรแล้ว"
  value={null}
  maxValue={1000}
/>
```

## 9 · Anti-patterns

| ❌ | ✅ | ทำไม |
|---|---|---|
| แถบเปล่าไม่มีตัวเลข | ตัวเลขแสดงเสมอ | สีอย่างเดียวสื่อความหมายไม่ได้ (SC 1.4.1) · component ไม่มี prop ให้ปิด |
| แถบใต้ "วงเงินสูงสุด 500,000" ของผู้ใช้ | `<EntityAmount>` ล้วน | ★★ ทำให้เพดานดูเหมือนเงินที่จะได้รับ (`GrantCard.md §3`) |
| `value={0}` เมื่อยังไม่รู้ยอด | `value={null}` | แถบว่างอ่านว่า "ยังไม่มีใครใช้โควตา" ซึ่งอาจตรงข้ามกับความจริง |
| ลบขอบรางเพราะ "ดูสะอาดกว่า" | ขอบ `edge-strong` เสมอ | โหมดมืด `sunken` = `canvas` **1.00:1** — รางหายทั้งเส้น |
| `tone="warning"` เมื่อโควตาใกล้หมด | `tone="danger"` | ไม่มี tone นี้ — yellow-500 บนราง sunken ได้ **1.49:1** |
| `<span>` เป็น label | RAC `<Label>` | แถบไม่มีชื่อ (axe: `progressbar-name`) |
| `transition-[width]` ลอย ๆ | `motion-safe:transition-[width]` | ALLOW list ของ reduced motion ไม่รวม `width` |
| ใช้แทน stepper ของฟอร์ม 4 ขั้น | `<CheckoutStepper>` | "เหลืออีก 25%" ไม่บอกว่าขั้นถัดไปต้องทำอะไร |
| หนีบตัวเลขที่แสดงตามแถบเมื่อ `value > maxValue` | แถบหนีบ ตัวเลขไม่หนีบ | ข้อมูลผิดของต้นทางต้องเห็น ไม่ใช่ถูกกลบให้ดูเรียบร้อย |
