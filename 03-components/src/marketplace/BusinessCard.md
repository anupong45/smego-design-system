## 1 · ภาพรวม

การ์ดของ **ธุรกิจหนึ่งราย** — ผลการจับคู่ธุรกิจ · รายชื่อผู้ผลิตที่แนะนำ · ไดเรกทอรีซัพพลายเออร์

### ★★ ทำไมถึงต้องมี

ก่อนหน้านี้ระบบมีการ์ดสำหรับ **สินค้า · บริการ · โครงการ · ทุน · สินเชื่อ · อบรม** แต่ไม่มีการ์ดสำหรับ **ธุรกิจ** ทั้งที่นี่คือมาร์เก็ตเพลส B2B ที่ผู้ขายทุกรายคือธุรกิจ

`EntityCard.md §8` สาธิต `SupplierCard` ไว้เป็นตัวอย่างการสร้าง wrapper ใหม่มาตลอด แต่ไม่เคยมีตัวจริง — ไฟล์นี้คือตัวจริง

### ❌ เมื่อไรที่ไม่ควรใช้

| สถานการณ์ | ใช้อะไรแทน | เหตุผล |
|---|---|---|
| โปรไฟล์เต็มของผู้ขาย | `<SellerProfile>` | การ์ดมีที่แค่ 3–4 คู่ ไม่ใช่ใบรับรองทั้งชุด + ข้อมูลภาษี |
| สินค้าของธุรกิจรายนี้ | `<ProductCard>` | คนละสิ่งที่ผู้ใช้กำลังเลือก |
| โครงการจับคู่ธุรกิจของรัฐ | `<ProgramCard>` | นั่นคือ*โครงการ* ไม่ใช่*ธุรกิจ* |
| ผลการค้นหาแบบผสมหลายชนิด | `<SearchResult>` | ต้องรองรับหลาย entity ในลิสต์เดียว |

### ★★★ `matchReason` ต้องเป็นข้อเท็จจริงที่ตรวจสอบได้

| ✅ | ❌ |
|---|---|
| "อยู่ในหมวดเดียวกันและจังหวัดเดียวกัน" | "เหมาะกับคุณ 92%" |
| "เคยผลิตให้ลูกค้าในหมวดของคุณ" | "AI แนะนำ" |
| "มีใบรับรอง GMP ตามที่คุณระบุ" | "ตรงกับความต้องการของคุณมาก" |

`01-brand.md` กำหนดว่า **ตัวเลขทุกตัวต้องบอกที่มาได้** — คะแนนความเหมาะสมที่ไม่มีสูตรเปิดเผยคือตัวเลขที่บอกที่มาไม่ได้ และมันสร้างความเชื่อถือปลอมในบริบทที่ผู้ใช้กำลังจะฝากงานผลิตจริงให้คนแปลกหน้า

## 2 · React API

```tsx
import { BusinessCard } from '@smego/ui';

<BusinessCard
  href="/business/thai-food"
  name="บริษัท ไทยฟู้ดโปรเซสซิ่ง จำกัด"
  isVerified
  category="รับจ้างผลิตอาหาร"
  province="สมุทรสาคร"
  matchReason="อยู่ในหมวดเดียวกันและจังหวัดเดียวกัน"
  certifications={['GMP', 'HACCP']}
  footer={<Button size="sm" fullWidth>ส่งคำขอจับคู่</Button>}
/>
```

| prop | type | ค่าเริ่มต้น | หมายเหตุ |
|---|---|---|---|
| `href` · `name` | `string` | — | **บังคับ** |
| `isVerified` | `boolean` | — | **บังคับ** · `false` = "ยังไม่ยืนยัน" ซึ่งเป็นข้อมูล ไม่ใช่การไม่มีข้อมูล |
| `category` · `province` | `string` | — | **บังคับ** |
| `matchReason` | `string` | — | ★★★ ข้อเท็จจริงที่ตรวจสอบได้เท่านั้น |
| `isRecommended` | `boolean` | `false` | ป้ายทอง "แนะนำ" · จำกัด 1–2 ใบต่อหน้า |
| `certifications` | `string[]` | — | ชื่อใบรับรองเป็นข้อความ |
| `employeeRange` | `string` | — | เช่น `"10–50 คน"` |
| `media` · `actions` · `footer` | `ReactNode` | — | |
| `isSelected` · `headingLevel` · `as` | | | ส่งต่อไป `EntityCard` |

### ★★ ไม่มี slot `amount` เลย

ธุรกิจไม่มีราคา · ตัดออกทั้งช่อง ไม่ใช่ส่งค่าว่าง — วิธีเดียวกับ `ProgramCard` ที่ *"ไม่มี slot `amount` เลย"*

ถ้าอยากแสดงราคาสินค้าของเจ้านี้ นั่นคือ `<ProductCard>` คนละใบกัน

## 3 · Variants

ไม่มี variant — ความต่างมาจากค่าที่ส่งเข้ามา

### eyebrow — ลำดับป้ายตายตัว

`แนะนำ (ทอง)` → `สถานะการยืนยัน` → `ใบรับรอง` — ลำดับอยู่ใน component ไม่ให้ผู้เรียกจัดเอง (A3 · เหตุผลเดียวกับที่ `Payment.md` ตรึงลำดับวิธีชำระเงิน)

| ป้าย | variant | เงื่อนไข |
|---|---|---|
| แนะนำ | `accent` (ทอง) | `isRecommended` |
| ยืนยันตัวตนแล้ว | `success` | `isVerified` |
| ยังไม่ยืนยันตัวตน | `neutral` | `!isVerified` — ★ **แสดงเสมอ ไม่ซ่อน** |
| ชื่อใบรับรอง | `neutral` `showIcon={false}` | ต่อรายการ |

### ★ ทองปรากฏได้กรณีเดียว

`Badge variant="accent"` ถูกจองไว้สำหรับ *"แนะนำ · ใหม่ · คัดสรร"* อยู่แล้ว (`Badge.tsx`) — **จำกัด 1–2 ใบต่อหน้า** เพราะทองหลายใบแย่งกัน = ไม่มีอะไรเด่น (`GrantCard.md §9` · ข้อ 02 §9)

การ์ดบังคับข้อนี้ไม่ได้ — เป็นความรับผิดชอบของหน้าที่เรียก และเป็นแถวใน checklist ของชั้น 04

### ★ ไม่มีไอคอนบนใบรับรอง

ไอคอนโดเมนไทย 14 ตัวยังไม่วาด (ข้อ 09 §8.2) และการหยิบไอคอนโล่/ดาวมาใส่คือ **การอ้างการรับรองด้วยสัญลักษณ์ที่ไม่มีใครรับรอง** (`ProductCard.md §9`)

## 4 · States

สืบทอดจาก `EntityCard` — **default · hover · focus-visible · active · selected** (รายละเอียดเหมือน `FundingCard.md §4`)

| state | สถานะ |
|---|---|
| default · hover · focus-visible · active · selected | ✅ สืบทอดจาก `EntityCard` |
| **disabled** | ★ ไม่มี — การ์ดเป็นลิงก์ ไม่ใช่ปุ่ม |
| **loading** | ★ ไม่มีในตัว — ผู้เรียกครอบด้วย `<SkeletonGroup>` |
| **error** | ★ ไม่มี — การ์ดไม่ทำ async |
| **empty** | ★ ไม่มี — ธุรกิจที่ไม่มีข้อมูลไม่ถูก render |

## 5 · Accessibility

| หัวข้อ | รายละเอียด |
|---|---|
| โครงสร้าง | `<article>` / `<li>` · หัวข้อ = ชื่อธุรกิจ |
| `matchReason` | ★ อยู่ใน `<dl>` **พร้อมชื่อ "เหตุผลที่เสนอ"** — ถ้าลอยเป็นข้อความเปล่า SR และผู้ใช้จะอ่านเป็นคำโฆษณาของผู้ขายเอง |
| สถานะยืนยัน | เป็นข้อความในป้าย ไม่ใช่สีอย่างเดียว (SC 1.4.1) |
| SC 1.4.10 | ✅ ไม่มี horizontal scroll ที่ 320px |

### วัดที่ 136px

| ตรวจอะไร | ผล |
|---|---|
| ชื่อทุกคู่ใน `<dl>` ไม่ถูกตัด | ✅ |
| ไม่มีข้อความล้นกล่อง | ✅ |
| ไม่มีคำว่า "บาท" โผล่ | ✅ — ยืนยันว่าไม่มีใครต่อ `amount` เข้ามา |

การ์ดนี้ไม่ติดหนี้ `EntityAmount` ที่ `FundingCard.md §5` บันทึกไว้ เพราะไม่มี `amount`

## 6 · Tailwind implementation

- ไม่มี CVA — wrapper ล้วน
- `items` ประกอบตามลำดับ *หมวด → จังหวัด → พนักงาน → เหตุผลที่เสนอ* · เหตุผลอยู่ท้ายสุดโดยตั้งใจ เพราะเป็นข้อมูลของ**ระบบ** ไม่ใช่ของ**ธุรกิจ**
- ไม่ส่ง prop `amount` เข้า `EntityCard` เลย — ไม่ใช่ส่ง `undefined` ให้ดูเหมือนมีช่อง

## 7 · Figma Variant

Component set `BusinessCard`

| property | values |
|---|---|
| `State` | `Default` · `Hover` · `Focus` · `Selected` |
| `Verified` | `True` · `False` |
| `Recommended` | `True` · `False` |
| `MatchReason` | `None` · `Present` |
| `Width` | `136` · `Default` |

**ที่ห้ามลืม**

- **frame `Verified = False` ต้องมีจริง** — ถ้ามีแต่แบบยืนยันแล้ว นักพัฒนาจะซ่อนป้ายเมื่อยังไม่ยืนยัน ซึ่งทำให้ผู้ซื้อสมมติว่าทุกรายยืนยันแล้ว
- **ห้ามสร้าง property `Amount`** — ไม่มีในโค้ดและจะไม่มี

## 9 · Anti-patterns

| ❌ | ✅ | ทำไม |
|---|---|---|
| `matchReason="เหมาะกับคุณ 92%"` | `"อยู่ในหมวดเดียวกันและจังหวัดเดียวกัน"` | ตัวเลขทุกตัวต้องบอกที่มาได้ (ข้อ 01) |
| ซ่อนป้ายเมื่อ `isVerified={false}` | แสดง "ยังไม่ยืนยันตัวตน" | ไม่แสดง → ผู้ซื้อสมมติว่ายืนยันแล้ว |
| ส่ง `amount` เข้ามาเพื่อโชว์ยอดขาย | ไม่ส่ง | ธุรกิจไม่มีราคา · ยอดขายเป็นข้อมูลของ `<SellerProfile>` |
| `isRecommended` ทุกใบในหน้ารวม | 1–2 ใบต่อหน้า | ทองหลายใบแย่งกัน = ไม่มีอะไรเด่น (ข้อ 02 §9) |
| `matchReason` เป็นข้อความลอยใต้ชื่อ | ใน `<dl>` พร้อมชื่อกำกับ | ข้อความลอยอ่านเป็นคำโฆษณาของผู้ขาย |
| ไอคอนโล่ข้างชื่อใบรับรอง | ข้อความล้วน | อ้างการรับรองด้วยสัญลักษณ์ที่ไม่มีใครรับรอง |
| ใช้แทน `<SellerProfile>` ในหน้าโปรไฟล์ | `<SellerProfile>` | การ์ดไม่มีที่ให้ข้อมูลภาษีและใบรับรองทั้งชุด |
| ใช้กับโครงการจับคู่ของรัฐ | `<ProgramCard>` | นั่นคือโครงการ ไม่ใช่ธุรกิจ |

## 10 · Quality Checklist

**หลักฐาน ไม่ใช่ความตั้งใจ** — ทุกแถวชี้ไปที่หัวข้อในไฟล์นี้หรือชื่อเทสที่รันได้จริง ไม่มีแถวไหนอธิบายพฤติกรรมซ้ำ (นั่นคืองานของ §4 และ §5)

| รายการ | สถานะ | หลักฐาน |
|---|---|---|
| การเข้าถึง (Accessibility) | ✅ | §5 · axe ผ่านใน `a11y/pass4.test.tsx` · เทส "`matchReason` มีชื่อกำกับ — ไม่ใช่ข้อความลอยที่อ่านเป็นคำโฆษณา" · "ใบรับรองเป็นข้อความล้วน ไม่มีไอคอน" (SC 1.4.1) |
| ตอบสนอง (Responsive) | ✅ | `e2e/pass4.spec.ts:17` (narrow-business) ไม่มีข้อความใดล้นกล่องที่ **136px** · `:41` ชื่อของทุกคู่ใน `<dl>` อยู่ครบ ไม่ถูกตัด · `:86` ไม่มีจำนวนเงินโผล่ |
| โหมดมืด (Dark Mode) | ✅ | โครงและเงามาจาก [`EntityCard`](./EntityCard.md) → `<Card>` ซึ่งใช้ `--elevation-*` ไม่ใช่ `shadow-*` · `lint-classes.mjs` 0 จุด — ทุกสีมาจาก token ที่ override ในโหมดมืดแล้ว |
| คุณสมบัติเชิงตรรกะ (Logical properties) | ✅ | `lint-quality.mjs` 0 จุด — ไม่มี `ml-`/`pl-`/`left-` ในไฟล์นี้ |
| คีย์บอร์ด (Keyboard) | ✅ | สืบทอดจาก [`EntityCard §5`](./EntityCard.md) — link overlay เป็น `<a href>` จริงจึงอยู่ใน tab order ตามธรรมชาติ · วงแหวน focus วาดที่**การ์ด** ไม่ใช่ที่ลิงก์ (SC 2.4.7) |
| กำลังโหลด (Loading) | — | §4 ประกาศไว้ตรง ๆ ว่า **"ไม่มีในตัว — ผู้เรียกครอบด้วย `<SkeletonGroup>`"** |
| ข้อผิดพลาด (Error) | — | §4 ประกาศไว้ตรง ๆ ว่า **"ไม่มี — การ์ดไม่ทำ async"** |
| ว่างเปล่า (Empty) | — | §4 ประกาศไว้ตรง ๆ ว่า **"ไม่มี — ธุรกิจที่ไม่มีข้อมูลไม่ถูก render"** · เทส "★ ยังไม่ยืนยันก็ยังแสดงป้าย ไม่ใช่ซ่อน" — ไม่แปลง "ไม่รู้" เป็น "ไม่มี" |
| Skeleton | — | ตัวแทนระหว่างโหลดอยู่ที่ระดับกริด (§4) |
| การเคลื่อนไหว (Animation) | ✅ | ไม่มี `transition` หรือ `animate` ในไฟล์นี้เลย — การเคลื่อนไหวเดียวคือ `transition-shadow` ที่สืบทอดมาจาก `<Card interactive>` ซึ่ง `box-shadow` อยู่ในรายการ ALLOW ของ `base.css §10` |
| ประสิทธิภาพ (Performance) | ✅ | สืบทอดจาก [`EntityCard §10`](./EntityCard.md) — `mt-auto` แทนการวัดความสูงด้วย JS · container query แทน ResizeObserver · ไม่มีความสูงตายตัว · เทส "★★ ไม่มี slot amount — ธุรกิจไม่มีราคา" จึงไม่มี container query ให้คำนวณ |
