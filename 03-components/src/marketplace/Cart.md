## 1 · ภาพรวม

ตะกร้าสินค้าที่ **เก็บของหลายร้านในใบเดียว แต่ชำระเงินแยกร้าน**

ชิ้นส่วนชุดเดียวกันประกอบได้ทั้ง **drawer** (ดูเร็วหลังกดเพิ่ม) และ **หน้าตะกร้าเต็ม** (แก้จำนวนหลายรายการ) — ไม่มีการเขียนสองชุด

กฎโดเมนทั้งหมดอยู่ใน [`04-patterns/05-cart-and-checkout.md`](../../../04-patterns/05-cart-and-checkout.md)

### ❌ เมื่อไรที่ไม่ควรใช้

| สถานการณ์ | ใช้อะไรแทน | เหตุผล |
|---|---|---|
| บริการ / งานที่ต้องตกลงขอบเขต | [`<BuyBox kind="service">`](./BuyBox.md) | ไม่มีสต็อก ไม่มีค่าขนส่ง ราคายังไม่นิ่ง |
| สรุปยอดในหน้าชำระเงิน | [`<CheckoutSummary>`](./Checkout.md) | ตะกร้าแก้ได้ · สรุปอ่านอย่างเดียว |
| รายการที่บันทึกไว้ดูภายหลัง | [`<WishlistGrid>`](./Wishlist.md) | ยังไม่ตั้งใจซื้อ |
| เทียบสเปกก่อนตัดสินใจ | [`<CompareTable>`](./Compare.md) | คนละขั้นของการตัดสินใจ |

## 2 · React API

```tsx
<CartList itemCount={4} sellerCount={2} isGuest>
  <CartSellerGroup
    sellerName="บจก. ไทยโรสเตอร์"
    subtotal={1_250_000}
    onCheckout={() => checkout('seller-1')}
  >
    <CartLineItem
      name="เครื่องคั่วกาแฟ TR-500"
      href="/p/tr-500"
      unitPrice={1_250_000}
      unit="เครื่อง"
      quantity={qty}
      onQuantityChange={setQty}
      onRemove={remove}
    />
  </CartSellerGroup>
</CartList>
```

| `maxQuantity` | `number` | — | จำนวนที่ผู้ขายมี |

## 3 · Variants

`CartLineItem` มี `compact` ตัวเดียว

| | เต็ม (หน้าตะกร้า) | `compact` (drawer) |
|---|---|---|
| รูปสินค้า | 64 → 80px | ซ่อน |
| ช่องจำนวน | `NumberInput` | `NumberInput` (เท่ากัน) |
| ยอดรวมแถว | แสดง | แสดง |

**ช่องจำนวนไม่ถูกย่อใน `compact`** — ปุ่มเพิ่ม/ลดที่เล็กลงจะไม่ผ่าน SC 2.5.8 และการแก้จำนวนคือเหตุผลหลักที่ผู้ใช้เปิดตะกร้า

## 4 · States

| state | ที่มา | ผล |
|---|---|---|
| ว่าง | `itemCount === 0` | ข้อความ + **วิธีทำให้ไม่ว่าง** + ปุ่ม |

## 5 · Accessibility

| เรื่อง | ข้อกำหนด |
|---|---|
| **SC 2.5.3** | ทุกปุ่มในแถวมีชื่อสินค้า · ปุ่มชำระมีชื่อร้าน |
| **SC 1.3.1** | กลุ่มร้านเป็น `<section>` + หัวข้อ · รายการเป็น `<ul>` / `<li>` |
| **SC 2.5.8** | ปุ่มนำออก 36×36 · ปุ่มเพิ่ม/ลด 24×24 |
| **SC 2.4.7** | drawer ไม่มี `overflow-hidden` ทับวงแหวน |
| **SC 2.1.2** | Esc ปิด drawer ได้ (RAC) |

### ★★★ ปุ่มในตะกร้า 10 รายการต้องแยกออกจากกัน

ตะกร้าที่มี 10 รายการมีปุ่ม "นำออก" 10 ปุ่มและช่อง "จำนวน" 10 ช่อง — ผู้ใช้ screen reader ที่ไล่ด้วยรายการปุ่มจะได้ยิน **"นำออก" สิบครั้งติดกัน**

ทุกปุ่มจึงมีชื่อสินค้าอยู่ในชื่อ: `นำ เครื่องคั่วกาแฟ TR-500 ออกจากตะกร้า`

ช่องจำนวนใช้ **ป้ายที่เห็น = "จำนวน"** แต่ **ชื่อที่ประกาศ = "จำนวนของ เครื่องคั่วกาแฟ TR-500"** — ยังผ่าน SC 2.5.3 เพราะข้อความที่เห็นเป็นส่วนหนึ่งของชื่อที่ประกาศ

### ★★★ drawer ต้องมีทางไปหน้าตะกร้าเต็มเสมอ

`fullCartHref` เป็น prop **บังคับ** ไม่มี `?`

แผงกว้าง 560px แก้จำนวนของสามร้านพร้อมกันไม่ไหว และผู้ใช้ที่ขยายตัวอักษร 200% (SC 1.4.4) เห็นได้ทีละรายการเดียว — ถ้าไม่มีทางออกไปหน้าเต็ม งานนั้นจะทำไม่ได้เลยบนอุปกรณ์บางเครื่อง

ปุ่มนั้นเป็น `<Link>` จริง ไม่ใช่ `<Button onPress={navigate}>` — ผู้ใช้ต้องเปิดแท็บใหม่และคัดลอก URL ได้

### ★★ ยอดรวมแถวเป็นข้อความ ไม่ใช่การคูณในหัวผู้ใช้

ราคาต่อหน่วย × จำนวน คือเลขที่ผู้ซื้อตรวจก่อนโอน · การให้คูณเองคือที่มาของการทักท้วงยอดหลังโอนแล้ว

ทุกจำนวนเงินใช้ `font-numeric tabular-nums` และ `minimumFractionDigits: 2` เหมือน `CheckoutSummary`

### ★ คำเตือน "ชำระแยกร้าน" อยู่ในตะกร้า ไม่ใช่ในหน้าชำระเงิน

ผู้ซื้อที่รู้ตอนหน้าชำระเงินว่าต้องโอนสามครั้ง คือผู้ซื้อที่รู้สายเกินไป

## 6 · Tailwind implementation

```tsx
<li className="grid min-w-0 gap-3 border-b border-edge-subtle py-4 last:border-b-0">
```

เส้นคั่นเป็น **ขอบตกแต่ง** (`edge-subtle` = 1.27:1) ซึ่งอยู่ในขอบเขตที่ระบบยกเว้นไว้ — ความหมายมาจากโครง `<li>` ไม่ใช่จากเส้น

```tsx
<DialogOverlay variant="drawer" side="end" size="md">
```

`side="end"` เพราะปุ่มเปิดอยู่มุมขวาบนของ `AppHeader` — แผงที่โผล่คนละฝั่งกับปุ่มที่กดทำให้ผู้ใช้ต้องกวาดตาหาว่าอะไรเปลี่ยน · ตัวกรองยังใช้ `start` เพราะบนจอกว้างมันคือแถบข้างซ้ายอยู่แล้ว

## 7 · Figma Variant

Component set **`CartLineItem`**

| Property | Values |
|---|---|
| `Layout` | `Full` · **`Compact (drawer)`** |
| `Stock` | `พอ` · `เหลือน้อยกว่าที่สั่ง` |

Component set **`Cart`**

| Property | Values |
|---|---|
| `Sellers` | `1` · **`2 (แยกชำระ)`** |

## 8 · Usage

```tsx
const groups = groupBySeller(cart.items);

<CartList
  itemCount={cart.items.length}
  sellerCount={groups.length}
  isGuest={!user}
  emptyAction={<Link href="/products">{s.cart.continueShopping}</Link>}
>
  {groups.map((g) => (
    <CartSellerGroup
      key={g.sellerId}
      sellerName={g.sellerName}
      sellerHref={`/s/${g.sellerId}`}
      subtotal={g.subtotal}
      onCheckout={() => router.push(`/checkout/${g.sellerId}`)}
    >
      {g.items.map((item) => (
        <CartLineItem
          key={item.id}
          name={item.name}
          href={`/p/${item.id}`}
          media={<img src={item.image} alt="" className="size-full object-cover" />}
          unitPrice={item.unitPrice}
          unit={item.unit}
          quantity={item.quantity}
          minQuantity={item.moq}
          maxQuantity={item.stock}
          onQuantityChange={(n) => cart.setQuantity(item.id, n)}
          onRemove={() => cart.remove(item.id)}
        />
      ))}
    </CartSellerGroup>
  ))}
</CartList>
```

## 9 · Anti-patterns

| ❌ | ✅ | ทำไม |
|---|---|---|
| ตะกร้าแยกต่อร้าน | ตะกร้าเดียวหลายร้าน | ผู้ซื้อ B2B เทียบหลายเจ้าในรอบเดียว |
| ปุ่ม "ชำระเงินทั้งหมด" ปุ่มเดียว | ปุ่มต่อร้าน | เงินเข้าบัญชีผู้ขายโดยตรง สลิปใบเดียวจับคู่หลายร้านไม่ได้ |
| บริการเข้าตะกร้า | `BuyBox kind="service"` | ค่าขนส่งและ VAT ของยอดที่ยังไม่นิ่ง = ตัวเลขโกหก |
| บังคับเข้าสู่ระบบตอนกดเพิ่ม | แขกใส่ได้ · ล็อกอินตอนชำระ | ขอตัวตนก่อนให้คุณค่า = ผู้ซื้อออกจากหน้า |
| `aria-label="นำออก"` | รวมชื่อสินค้า | 10 ปุ่มชื่อเดียวกัน (SC 2.5.3) |
| drawer ที่ไม่มีทางไปหน้าเต็ม | `fullCartHref` บังคับ | ที่ 200% zoom เห็นทีละรายการ |
| ปุ่ม "ดูตะกร้าทั้งหมด" เป็น `<Button>` | `<Link>` | ต้องเปิดแท็บใหม่และคัดลอก URL ได้ |
| ย่อปุ่มเพิ่ม/ลดใน drawer | ขนาดเดิม | ต่ำกว่า 24×24 ไม่ผ่าน SC 2.5.8 |
| แสดงแต่ราคาต่อหน่วย | + ยอดรวมแถว | ผู้ใช้ไม่ควรต้องคูณเอง |
| บอกว่า "ชำระแยกร้าน" ที่หน้าชำระเงิน | บอกในตะกร้า | รู้สายเกินไป |
| ตะกร้าว่างแสดงแค่ "ไม่มีสินค้า" | + วิธีทำให้ไม่ว่าง | ข้อ 01 |

## 10 · Quality Checklist

**หลักฐาน ไม่ใช่ความตั้งใจ** — ทุกแถวชี้ไปที่หัวข้อในไฟล์นี้หรือชื่อเทสที่รันได้จริง ไม่มีแถวไหนอธิบายพฤติกรรมซ้ำ (นั่นคืองานของ §4 และ §5)

| รายการ | สถานะ | หลักฐาน |
|---|---|---|
| การเข้าถึง (Accessibility) | ✅ | §5 · axe ผ่านใน `a11y/pass5.test.tsx` · เทส **"★★★ ทุกปุ่มในแถวมีชื่อสินค้า (SC 2.5.3)"** · "★★ ยอดรวมของแถวแสดงเป็นข้อความ ไม่ให้ผู้ใช้คูณเอง" |
| ตอบสนอง (Responsive) | ✅ | `min-w-0` · `SC 1.4.4` ยอดเงินยังอ่านครบเมื่อขยายตัวอักษร 200% · drawer เต็มจอที่มือถือและเป็นแผงข้างที่จอกว้าง |
| โหมดมืด (Dark Mode) | ✅ | drawer ใช้ `--elevation-*-overlay` · `lint-classes.mjs` 0 จุด — ทุกสีมาจาก token ที่ override ในโหมดมืดแล้ว |
| คุณสมบัติเชิงตรรกะ (Logical properties) | ✅ | ใช้คู่ `ms-`/`me-` อยู่แล้ว · `lint-quality.mjs` 0 จุด — ไม่มี `ml-`/`pl-`/`left-` ในไฟล์นี้ |
| คีย์บอร์ด (Keyboard) | ✅ | `SC 2.1.2` drawer ปิดด้วย `Esc` และคืน focus (กลไกเดียวกับ [`<Dialog>`](../feedback/Dialog.md) ที่ `e2e/wcag22.spec.ts:228` วัดไว้) · เทส "★★★ drawer มีทางไปหน้าตะกร้าเต็ม **และเป็นลิงก์จริง**" |
| กำลังโหลด (Loading) | ✅ | §4 "กำลังไปหน้าชำระ" · สถานะอยู่ที่ปุ่มชำระของร้านนั้น ไม่ใช่ทั้งตะกร้า |
| ข้อผิดพลาด (Error) | — | ข้อผิดพลาดของการชำระเงินอยู่ที่ [`Checkout`](./Checkout.md) · ตะกร้าเป็นที่รวบรวม ไม่ใช่ที่ทำธุรกรรม |
| ว่างเปล่า (Empty) | ✅ | §4 "ว่าง" · เทส **"★ ตะกร้าว่างบอกวิธีทำให้ไม่ว่าง"** — มี `emptyAction` เป็นทางออก ไม่ใช่แค่ข้อความ |
| Skeleton | — | ตะกร้าอ่านจาก store ในเครื่องซึ่งมาทันที |
| การเคลื่อนไหว (Animation) | — | ไม่มี `transition` หรือ `animate` ในไฟล์นี้เลย — ยอดเงินห้ามขยับระหว่างที่ผู้ใช้อ่าน |
| ประสิทธิภาพ (Performance) | ✅ | ยอดรวมของแต่ละร้านส่งมาเป็นค่า ไม่ได้บวกจาก DOM · §4 "หลายร้าน" แยกปุ่มชำระตั้งแต่ต้นจึงไม่ต้องคำนวณใหม่ทั้งตะกร้า |
