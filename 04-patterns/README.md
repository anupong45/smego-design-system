# SME.GO Design System — 04 Marketplace Patterns

**ชั้นที่ตอบว่า "ประกอบยังไง" ไม่ใช่ "มีอะไรบ้าง"**

ชั้นนี้ **ไม่มีโค้ด** — ชั้น 03 เป็นเจ้าของ component ทุกตัว ที่นี่เป็นเจ้าของ **การตัดสินใจว่าเมื่อไรใช้ตัวไหน และประกอบเข้าด้วยกันอย่างไร**

---

## ทำไมต้องมีชั้นนี้

ชั้น 03 มี 62 component และแต่ละไฟล์มีตาราง *"❌ เมื่อไรที่ไม่ควรใช้"* ของตัวเอง ซึ่งดีมาก — แต่มันแปลว่า **คำตอบของคำถาม "ของแบบนี้ใช้การ์ดไหน" กระจายอยู่ใน §1 ของ 8 ไฟล์** และหาเจอก็ต่อเมื่อเปิดไฟล์ที่ถูกอยู่แล้ว

คนที่กำลังสร้างหน้าใหม่ไม่รู้ว่าต้องเปิดไฟล์ไหน · ชั้นนี้จึงเริ่มจาก **คำถามของผู้สร้างหน้า** แล้วชี้ไปที่ component ไม่ใช่เริ่มจาก component

## หลักการเขียนของชั้นนี้

1. **ทุกแถวชี้ไป component ที่มีจริงและ export แล้ว** — ห้ามอ้างของที่ยังไม่สร้าง โดยไม่ติดป้ายว่ายังไม่มี
2. **ทุกกฎมีเกณฑ์ที่ชี้ผิด/ถูกได้** ไม่ใช่ "ควรพิจารณา"
3. **เคสก้ำกึ่งต้องตัดสินไว้ล่วงหน้า** — ถ้าเอกสารไม่ตัดสิน แต่ละคนจะตัดสินเอง แล้วได้ระบบที่ไม่สม่ำเสมอ (A3)
4. **อ้าง `DESIGN-PRINCIPLES.md` เมื่อเป็นการตัดสินข้อขัดแย้ง** ไม่ใช่ตัดสินเงียบ ๆ
