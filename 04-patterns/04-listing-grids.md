# 04 · กริดรายการ

**ชั้น 04** · Marketplace Patterns

เอาการ์ดมาเรียงเป็นหน้ายังไง — โครงสร้าง · สถานะ · และสิ่งที่การ์ดบังคับเองไม่ได้

---

## 1 · โครงมาตรฐานของหน้ารายการ

```tsx
<Container size="content">
  <CategoryBreadcrumb items={crumbs} />
  <CategoryNav items={categories} currentId={id} allHref="/all" />

  <Grid preset="sidebar">
    <FilterPanel groups={groups} … />          {/* drawer ใต้ lg */}

    <div className="min-w-0">
      <FilterChipRow filters={active} … />     {/* ★ เหนือผลลัพธ์ ไม่ใช่ในแผง */}

      <SearchResult count={128} query={q} toolbar={<SortSelect />}>
        <Grid as="ul" preset="product-filtered">
          {items.map((p) => <ProductCard key={p.id} as="li" {...p} />)}
        </Grid>
      </SearchResult>
    </div>
  </Grid>

  <CompareBar items={compare} … />
</Container>
```

### ★ สามข้อที่ผิดบ่อยที่สุดในโครงนี้

1. **`FilterChipRow` อยู่เหนือผลลัพธ์ ไม่ใช่ในแผงตัวกรอง** — ตัวกรองที่เลือกไว้ต้องเห็นค้างตลอด ไม่ยุบเป็น "ตัวกรอง (3)" (B3 · ข้อ 01 §4.3)
2. **`as="li"` บนการ์ดเมื่อกริดเป็น `<ul>`** — ไม่งั้น `<ul>` มีลูกเป็น `<article>` ซึ่งผิด HTML และ SR ไม่ประกาศจำนวนรายการ
3. **หมวดหมู่ไม่ใช่ตัวกรอง** — `CategoryNav` คือ *ตำแหน่งที่อยู่* · ตัวกรองที่ยกเลิกได้คือ `Chip`

## 2 · เลือก preset ของ `Grid`

| preset | คอลัมน์ | ใช้กับ |
|---|---|---|
| `product` | 2 → 3 → 4 → 5 | กริดสินค้าเต็มความกว้าง ไม่มีแถบตัวกรอง |
| `product-filtered` | 2 → 3 → 4 | กริดสินค้าที่มีแถบตัวกรองข้าง |
| `cards` | 1 → 2 → 3 | **การ์ดใหญ่ — `GrantCard` · `FundingCard` · `ProgramCard` · `TrainingCard`** |
| `split` | 1 → 2 | สองคอลัมน์ |
| `sidebar` | 1 → `[280px 1fr]` | โครงหน้าที่มีแถบตัวกรอง |

**การ์ดเงินและโครงการใช้ `cards` ไม่ใช่ `product`** — 5 คอลัมน์ที่ xl ทำให้การ์ดกว้าง ~136px ซึ่งเป็นเคสที่ `EntityAmount` ยังแสดงตัวเลข 7 หลักไม่ได้ (Known Gaps ข้อ 9) และการ์ดกลุ่มนี้มี `<dl>` 4–6 แถวที่ต้องการที่มากกว่า

`gutter` ปล่อยเป็น `responsive` (16px → 24px) เว้นแต่มีเหตุผลวัดได้

## 3 · สถานะของกริด — ครบทั้ง 4

| state | ทำอะไร | component |
|---|---|---|
| **loading** | โครงการ์ดที่รูปร่างตรงกับของจริง · ประกาศ "กำลังโหลด" **ครั้งเดียว** | `<SkeletonGroup>` ครอบ `<Grid>` |
| **empty** | ข้อความ + **ทางออก** ไม่ใช่แค่ "ไม่พบผลลัพธ์" | `<SearchResult emptyAction={…}>` |
| **error** | อะไรผิด → ทำไม → แก้อย่างไร + ปุ่มลองใหม่ | `role="alert"` |
| **partial** | บางการ์ดข้อมูลไม่ครบ | การ์ดแสดง "ยังไม่ประกาศ" เอง — ไม่ต้องกรองออก |

### ★ อย่ากรองการ์ดที่ข้อมูลไม่ครบออกจากผลลัพธ์

โครงการที่หน่วยงานยังไม่ประกาศเงื่อนไขหลักประกันยังเป็นโครงการที่มีจริง — การซ่อนทำให้ผู้ใช้ไม่เห็นสิ่งที่มีอยู่ (B1) · การ์ดออกแบบมาให้แสดง "ยังไม่ประกาศ" ได้อยู่แล้ว

## 4 · ★★ สิ่งที่การ์ดบังคับเองไม่ได้ — เป็นหน้าที่ของหน้า

| กฎ | เกณฑ์ | ทำไมการ์ดบังคับไม่ได้ |
|---|---|---|
| **ทอง ≤ 1–2 ใบต่อหน้า** | นับ `isRecommended` + CTA ทอง | การ์ดไม่รู้ว่ามีใบอื่นกี่ใบ |
| **CTA หลัก 1 ตัวต่อ 1 หน้าจอ** | น้ำเงินทึบ ~12% ของพื้นที่ | เดียวกัน |
| **`headingLevel` ตรงกับลำดับจริง** | h1 → h2 → h3 ไม่กระโดด | การ์ดไม่รู้ว่าอยู่ใต้หัวข้ออะไร |
| **`aria-current="step"` มีอันเดียว** | ในทั้ง stepper | — |
| **การ์ดชนิดเดียวกันทั้งกริด** | ห้ามผสม `GrantCard` กับ `FundingCard` ในกริดเดียวโดยไม่มีหัวข้อแยก | ดูข้อ 5 |

---

## 5 · ★★★ ห้ามผสมทุนกับสินเชื่อในกริดเดียวโดยไม่แยกหัวข้อ

นี่คือสถานการณ์ที่การแยก `GrantCard` กับ `FundingCard` ออกจากกันจะ**ไม่ช่วยอะไรเลย**ถ้าหน้าเอามาเรียงปนกัน

ผู้ใช้ที่กวาดตาผ่านกริดเห็นตัวเลขเรียงกัน 6 ใบ — ความต่างมีแค่คำว่า "กู้" ในบรรทัด label ซึ่งเล็กและอ่านทีหลัง

**ถ้าต้องแสดงทั้งสองในหน้าเดียว ให้แยกเป็น 2 section พร้อมหัวข้อ:**

```tsx
<Section>
  <h2>ทุนและเงินอุดหนุน — ไม่ต้องคืน</h2>
  <Grid as="ul" preset="cards">{grants.map(…)}</Grid>
</Section>

<Section>
  <h2>สินเชื่อ — ต้องชำระคืน</h2>
  <Grid as="ul" preset="cards">{loans.map(…)}</Grid>
</Section>
```

หัวข้อทำงานที่ label บนการ์ดทำไม่ได้ — มันตั้งบริบทก่อนที่ตาจะไปถึงตัวเลข

## 6 · การเปรียบเทียบ

| กฎ | ค่า | ที่มา |
|---|---|---|
| จำนวนสูงสุด | **4 รายการ** | 8 ทำให้คอลัมน์แคบเกินอ่าน |
| ปุ่ม "ดูการเปรียบเทียบ" | `isDisabled` เมื่อมี < 2 | เทียบของชิ้นเดียวไม่มีความหมาย |
| ที่ 320px | **สลับเป็นแนวตั้ง** จัดกลุ่มตามคุณสมบัติ | เลื่อนแนวนอน = เห็นสองค่าพร้อมกันไม่ได้ |
| แถบว่าง | `return null` | กินพื้นที่ก้นจอโดยไม่ให้อะไร |
| ความสูงแถบ | ประกาศ `--compare-bar-height` จากค่าที่วัดจริง | ค่าเริ่มต้น 56px แต่วัดได้ **77px** → 3 element ถูกบังจนมิด (SC 2.4.11) |

## 7 · checklist ก่อนส่งหน้ารายการ

```markdown
- [ ] การ์ดเป็นชนิดเดียวกันทั้งกริด หรือแยก section พร้อมหัวข้อ
- [ ] `as="li"` เมื่อ Grid เป็น `<ul>`
- [ ] `headingLevel` ตรงกับลำดับหัวข้อจริงของหน้า
- [ ] preset ตรงกับชนิดการ์ด (การ์ดเงิน/โครงการ = `cards`)
- [ ] FilterChipRow อยู่เหนือผลลัพธ์ เห็นค้างตลอด
- [ ] ครบ 4 สถานะ: loading · empty (มีทางออก) · error (มีปุ่มลองใหม่) · partial
- [ ] ทอง ≤ 2 ใบ · CTA น้ำเงินทึบ 1 ตัวต่อหน้าจอ
- [ ] SearchResult ประกาศจำนวนผลลัพธ์ให้ SR
- [ ] ทดสอบ 320px และ 1280px — ไม่มี horizontal scroll
- [ ] แถบล่างประกาศตัวแปรความสูงของตัวเองจากค่าที่วัดจริง
```

## 8 · ❌ / ✅

| ❌ | ✅ | ทำไม |
|---|---|---|
| ทุนกับสินเชื่อเรียงปนกันในกริดเดียว | แยก section พร้อมหัวข้อ | label เล็กเกินกว่าจะกันการอ่านผิดตอนกวาดตา |
| `preset="product"` กับ `GrantCard` | `preset="cards"` | 5 คอลัมน์ที่ xl = การ์ดกว้าง ~136px ซึ่งแคบเกินสำหรับ `<dl>` 4–6 แถว |
| `<article>` เป็นลูกของ `<ul>` | `as="li"` | ผิด HTML · SR ไม่ประกาศจำนวนรายการ |
| ตัวกรองที่เลือกยุบเป็น "ตัวกรอง (3)" | `FilterChipRow` เหนือผลลัพธ์ | ผู้ใช้ต้องจำว่าเลือกอะไรไว้ (B3) |
| กรองการ์ดที่ข้อมูลไม่ครบออก | แสดงพร้อม "ยังไม่ประกาศ" | ซ่อนสิ่งที่มีอยู่จริง (B1) |
| "ไม่พบผลลัพธ์" เฉย ๆ | + `emptyAction` | สถานะว่างต้องมีทางออก |
| skeleton ที่รูปร่างไม่ตรงกับของจริง | ตรงกับการ์ดจริง | มุมกระตุกตอนโหลดเสร็จ · ผู้ใช้คาดผิด |
| ป้าย "แนะนำ" ทุกใบ | 1–2 ใบต่อหน้า | ทองหลายใบแย่งกัน = ไม่มีอะไรเด่น |
| แถบล่างเขียน `body.style` | ตัวแปรของตัวเอง | last-writer-wins เมื่อมีสองแถบ |
