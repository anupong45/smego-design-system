# 02 · Color System / ระบบสี

**SME.GO Marketplace** · Foundation Layer · WCAG 2.2 AA

ทุกค่า contrast ในเอกสารนี้ **คำนวณจริงด้วยสูตร WCAG 2.x relative luminance** ไม่ใช่การประมาณ · พื้นอ้างอิงคือ `neutral-0` #FFFFFF (โหมดสว่าง) และ `neutral-950` #12141A (โหมดมืด)

**เกณฑ์:** AAA ≥ 7:1 · AA ≥ 4.5:1 · AA-Large / non-text ≥ 3:1 · ต่ำกว่า 3:1 = FAIL

---

## ภาพรวม / Overview

ระบบสีนี้มี 6 ramp และ 1 alias

| Ramp | Hue | บทบาท |
|---|---|---|
| **Primary** | 203° | สิ่งที่กดได้ · สถานะ active · **และ Info (alias)** |
| **Neutral** | 220° | พื้น ขอบ ตัวอักษร — ~85% ของพิกเซลทั้งหมด |
| **Gold** | 36° | จุดเน้นแบรนด์เท่านั้น — **ห้ามใช้เป็นสถานะ** |
| **Success** | 152° | สำเร็จ · อนุมัติ · ยืนยันแล้ว |
| **Warning** | 48° | เตือน · ต้องตรวจสอบ · ใกล้หมดเวลา |
| **Danger** | 2° | ผิดพลาด · ปฏิเสธ · ลบ |
| **Info** | — | **alias ทับ Primary — ไม่มี ramp ของตัวเอง** |

## 7 · Info — alias ทับ Primary

**ไม่มี ramp ของตัวเอง** ประหยัด token 11 ตัว และเลี่ยงปัญหา "น้ำเงินสองเฉดที่แยกไม่ออก"

| Semantic token | alias ไปที่ | ค่า |
|---|---|---|
| `--color-info-surface` | `primary-50` | `#F0F9FE` |
| `--color-info-edge` | `primary-300` | `#88C9F2` |
| `--color-info-icon` | `primary-600` | `#0077C1` |
| `--color-info-text` | `neutral-900` | `#1D2128` |

### กฎ tint-only

Info แสดงผลได้ **แบบเดียวเท่านั้น**

```
พื้น primary-50 + ขอบ 1px primary-300 + ไอคอน primary-600 + ตัวอักษร neutral-900
```

**ห้ามเป็นพื้นทึบเด็ดขาด** เพราะกฎ *"น้ำเงินทึบ = กดได้"* จากข้อ 01 ต้องเป็นจริงทุกที่

**ผลการวัด**

| คู่สี | ค่า | ผล |
|---|---|---|
| `primary-600` ไอคอน บน `primary-50` | **4.47:1** | ✅ ผ่าน 3:1 สำหรับไอคอน (SC 1.4.11) |
| `neutral-900` ตัวอักษร บน `primary-50` | **15.1:1** | ✅ AAA |
| `primary-300` ขอบ บนพื้นขาว | 1.80:1 | ขอบตกแต่ง — **ยกเว้นจาก 1.4.11** |

**หมายเหตุเรื่องขอบ:** ขอบของ Info banner ไม่ผ่าน 3:1 แต่ **ไม่จำเป็นต้องผ่าน** เพราะ SC 1.4.11 ยกเว้นขอบที่เป็นการตกแต่ง — ความหมายถูกสื่อด้วย **ไอคอน (4.47:1) และตัวอักษร (15.1:1)** ซึ่งผ่านทั้งคู่ ถ้าต้องการขอบที่ผ่าน 3:1 จริง ต้องใช้ `primary-500` (3.46:1)

เดิมโจทย์ระบุขอบเป็น `primary-200` — **เปลี่ยนเป็น `primary-300`** เพราะ `primary-200` ที่ 1.39:1 จางเกินกว่าจะเห็นขอบได้จริง

## 9 · ⚠️ ระยะห่างระหว่าง Gold กับ Warning — ข้อจำกัดที่ต้องรู้

นี่คือจุดอ่อนที่รู้ตัวของระบบ ต้องบันทึกไว้ตรง ๆ

| | Gold-500 | Warning-500 |
|---|---|---|
| HEX | `#EC9513` | `#F2C40D` |
| Hue | 36° | 48° |
| Relative luminance | 0.393 | 0.582 |

- **ระยะห่าง hue = 12°**
- **contrast ระหว่างสองสี = 1.43:1**

**ต้องแก้คำพูดก่อนหน้าให้ถูก:** ก่อนหน้านี้ผมบอกว่าการแยกด้วยความสว่างจะ *"ทนต่อภาวะตาบอดสีได้ดีกว่าการห่างกัน 17°"* — **นั่นพูดเกินจริง** เมื่อวัดจริงได้ 1.43:1 ซึ่งเป็นความต่างที่ *พอเห็นได้* แต่ **ไม่ใช่การแยกที่แข็งแรง**

ผลการวัดที่ถูกต้อง: การจับคู่ 36°/48° **ดีกว่า** คู่เดิม (40°/32° ที่ห่าง 8° และความสว่างใกล้กันมาก) แต่ **ยังไม่ใช่ระยะห่างที่ปลอดภัย**

### สิ่งที่รับน้ำหนักจริง ไม่ใช่สี

1. **ทองห้ามใช้เป็นสถานะ** ทุกกรณี — ทองปรากฏได้แค่ที่ CTA แบรนด์และ badge แบรนด์
2. **สถานะทุกอันต้องมีไอคอน + ข้อความกำกับ** ไม่พึ่งสีเพียงอย่างเดียว (SC 1.4.1)
3. **ทองไม่มีรูปแบบ banner** — ระบบไม่มี `gold banner` ให้ใช้ผิด จึงไม่มีทางสับสนกับ warning banner
4. **ตัวอักษรบนพื้นทั้งสองใช้ `neutral-950` เหมือนกัน** จึงไม่มีความต่างที่จะพลาดได้

**สรุป:** ความแตกต่างเชิงสีอย่างเดียว **ไม่เพียงพอ** — กฎการใช้งานและการมีไอคอน/ข้อความกำกับคือสิ่งที่ทำให้ระบบนี้ใช้ได้จริง

### 📌 แก้ความแม่นยำ — กฎการตั้งชื่อที่ยืนยันด้วยการ build จริง

ฉบับแรกของเอกสารนี้ระบุว่า `--color-text-primary` จะสร้าง utility `text-primary` และ `--color-border-strong` จะสร้าง `border-strong` — **ทั้งสองข้อผิด** ตรวจแล้วด้วยการ build จริงบน **Tailwind v4.3.3**

namespace `--color-*` เป็น **แบน** และใช้ร่วมกันระหว่าง `bg-` / `text-` / `border-` — ชื่อ token คือ suffix ของ utility **ตรง ๆ ไม่มีการตัดคำ**

| ชื่อ token | utility ที่ได้จริง |
|---|---|
| `--color-text-primary` | `text-text-primary` ❌ ไม่ใช่ `text-primary` |
| `--color-border-strong` | `border-border-strong` ❌ ไม่ใช่ `border-strong` |
| `--color-bg-surface` | `bg-bg-surface` ❌ ไม่ใช่ `bg-surface` |

**ผลที่ตามมา: ห้ามใส่ชื่อ property ลงในชื่อ token** ชื่อทั้งหมดในระบบจึงถูกออกแบบจาก *"utility ที่ต้องการอ่านใน markup"* ย้อนกลับมาเป็นชื่อ variable

| ชื่อ token ที่ใช้จริง | utility | เดิมเขียนไว้ว่า |
|---|---|---|
| `--color-surface` | `bg-surface` | ~~`--color-bg-surface`~~ |
| `--color-fg` | `text-fg` | ~~`--color-text-primary`~~ |
| `--color-fg-muted` | `text-fg-muted` | ~~`--color-text-muted`~~ |
| `--color-on-accent` | `text-on-accent` | ~~`--color-text-on-accent`~~ |
| `--color-edge-strong` | `border-edge-strong` | ~~`--color-border-strong`~~ |
| `--color-focus-ring` | `outline-focus-ring` · `ring-focus-ring` | ~~`--focus-ring`~~ |

**ไม่มีชื่อชนกัน** — `text-fg` (สีตัวอักษรหลัก) กับ `text-primary-600` (สีแบรนด์) เป็นชื่อที่ต่างกันชัดเจน ต่างจากที่ฉบับแรกกังวลไว้

## 🧠 Decision Rationale

### ทำไม primary-600 ไม่ใช่ primary-500
#0077C1 บนพื้นขาวได้ 4.76:1 — ผ่าน AA เกินมาแค่ **0.26** ถ้าวางไว้ที่ 500 (ตำแหน่งกลาง ramp ตามแบบ Material) ปุ่มหลักจะทำงานอยู่บนขอบเกณฑ์ และทุก state ที่ hover ต้องเข้มลง ทำให้ปลายบนของ ramp บีบตัว การวางที่ 600 ทำให้ยังมี 500 และ 400 เหลือไว้ใช้เป็นสีตกแต่ง สีในกราฟ และตัวอักษรโหมดมืด — ซึ่ง `primary-400` ที่ 7.18:1 บนพื้นมืด **คือสิ่งที่ทำให้โหมดมืดใช้งานได้จริง**

### ทำไม neutral saturation จำกัดที่ 12%
Marketplace คือที่ที่คนตัดสินสีผ้าและสีอาหารจากรูปย่อ พื้นผิวโทนน้ำเงินจัดจะทำให้เห็นสีสินค้าเพี้ยน แต่ถ้าเป็นเทากลางสนิท (0%) จะดูหมอง ไม่เข้ากับน้ำเงินอมฟ้าของแบรนด์ 4–12% คือช่วงที่พื้นผิว *เข้ากับแบรนด์* แต่ *ไม่รบกวนภาพสินค้า* — และผลตรวจยืนยันว่าขั้น 300–700 อยู่ที่ 12/10/9/10/11% อยู่ในกรอบทั้งหมด

### ทำไม border-edge-strong เป็นคนละ token กับ border-edge
เพราะ **มีสองงานที่มีข้อกำหนดต่างกันจริง** ขอบ card คือการตกแต่ง SC 1.4.11 ยกเว้น จึงใช้ `neutral-300` ที่ดูนุ่มได้ แต่ขอบ input คือขอบเขตของ UI component ต้องผ่าน 3:1 — `neutral-300` ที่ 1.56:1 ไม่ผ่าน ระบบที่ใช้ token เดียวสำหรับสองงานนี้จะต้องเลือกระหว่าง "สวยแต่ไม่ผ่าน" กับ "ผ่านแต่ขอบ card หนาไป" การแยกเป็นสอง token ทำให้ได้ทั้งสองอย่าง

### ทำไมทองและเหลืองใช้ตัวอักษรเข้ม ไม่ใช่ขาว
เพราะสีอิ่มตัวที่ hue 36–48° มี luminance สูงตามธรรมชาติ ตัวอักษรขาวได้ 2.37:1 และ 1.66:1 — ไม่ผ่านเกณฑ์ใดเลย ไม่ใช่เรื่องรสนิยม แต่เป็นข้อจำกัดทางกายภาพของสีเหลือง-ส้ม ระบบจึงมี `--color-on-accent` แยกไว้ต่างหาก เพื่อให้ developer ไม่ต้องจำ และไม่มีทางเขียน `text-white` บนพื้นทองได้โดยไม่ผิด lint

### ทำไม Info ไม่มี ramp ของตัวเอง
ประหยัด token 11 ตัว และหลีกเลี่ยงปัญหาคลาสสิกคือ "น้ำเงินสองเฉดที่ขั้น 50/100 แยกไม่ออกอยู่ดี" — จ่ายค่า token ไปโดยไม่ได้การแยกกลับมา ราคาที่ต้องจ่ายแทนคือ **กฎ tint-only ต้องเป็นจริง 100%** ถ้ามีที่ไหนใช้พื้นน้ำเงินทึบกับสิ่งที่กดไม่ได้ ผู้ใช้จะเริ่มไม่แน่ใจว่าอะไรกดได้ และหน้าโครงการรัฐที่มีข้อความแจ้งเยอะจะเสียหายที่สุด

### ทำไมต้องเพิ่ม neutral-850
เพราะข้อ 9 กำหนดว่าโหมดมืดสร้างลำดับชั้นจากความสว่างพื้นผิว ไม่ใช่เงา ซึ่งต้องมี **3 ขั้น** (canvas → surface → raised) ramp มาตรฐาน 50–950 มีแค่ 900 และ 950 ในช่วงมืด — ไม่พอ ถ้าใช้ 800 เป็น raised จะสว่างเกินไป (14.23:1 บนพื้นขาว แปลว่าอ่อนกว่า 850 มาก) ทำให้ modal ในโหมดมืดดูลอยผิดปกติ

### ทำไมบันทึกจุดอ่อนของ Gold/Warning ไว้ในเอกสาร
เพราะการวัดจริงได้ 1.43:1 ซึ่งขัดกับที่ผมเคยพูดไว้ว่าการแยกด้วยความสว่างจะแข็งแรงกว่าระยะห่าง hue 17° การซ่อนข้อจำกัดนี้จะทำให้คนรุ่นถัดไปคิดว่าสีสองอันนี้แยกกันได้ดี แล้วออกแบบโดยพึ่งสีอย่างเดียว การเขียนไว้ตรง ๆ ทำให้กฎ *"ทองไม่ใช่สถานะ"* และ *"ทุกสถานะต้องมีไอคอน"* มีเหตุผลรองรับ ไม่ใช่กฎที่ดูจุกจิกไม่มีที่มา
