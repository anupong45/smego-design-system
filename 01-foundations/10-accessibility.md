# 10 · Accessibility Rules / กฎการเข้าถึง

**SME.GO Marketplace** · Foundation Layer · **WCAG 2.2 ระดับ AA**

ข้อสุดท้ายของชั้น Foundation — รวบกฎการเข้าถึงทั้งหมด และ **ตรวจความสอดคล้องข้ามทั้ง 10 ข้อ**

## ภาพรวม / Overview

**WCAG 2.2 AA เป็นเกณฑ์ผ่าน/ไม่ผ่าน** ไม่ใช่เป้าที่ทำได้ก็ดี — component ที่ไม่ผ่านถือว่ายังไม่เสร็จ ไม่ merge

WCAG 2.2 เพิ่มเกณฑ์ใหม่ **6 ข้อ** ซึ่งทีมส่วนใหญ่ยังไม่ได้ตรวจ และ **4 ข้อในนั้นกระทบ SME.GO โดยตรง** — ดูข้อ 6

## 1 · Keyboard

### 1.1 ปุ่มพื้นฐาน

| ปุ่ม | ต้องทำอะไร |
|---|---|
| `Tab` / `Shift+Tab` | เลื่อนตามลำดับสายตา — **ห้ามใช้ `tabindex` ค่าบวก** |
| `Enter` | เปิดใช้งานปุ่มและลิงก์ · ส่งฟอร์ม |
| `Space` | เปิดใช้งาน**ปุ่มเท่านั้น** (ไม่ใช่ลิงก์) · เลือก checkbox |
| `Esc` | ปิด overlay ทุกชนิด — modal · drawer · dropdown · tooltip |
| `↑ ↓ ← →` | เลื่อนภายใน composite widget (tabs · menu · listbox · radio group) |
| `Home` / `End` | ไปรายการแรก/สุดท้ายใน composite widget |

### 1.2 Roving tabindex สำหรับ composite widget

Widget ที่มีลูกหลายตัวต้องกิน **หนึ่ง tab stop** ไม่ใช่หนึ่งตัวต่อลูก

| Widget | Tab เข้า | ลูกศร |
|---|---|---|
| Tabs | tab ที่ active | เลื่อนระหว่าง tab |
| Menu | รายการแรก | เลื่อนระหว่างรายการ |
| Radio group | ตัวที่เลือกไว้ (หรือตัวแรกถ้ายังไม่เลือก) | เลื่อนและ**เลือกทันที** |
| Listbox / Combobox | ตัวที่เลือกไว้ | เลื่อน · `Enter` ยืนยัน |
| Toolbar ปุ่มไอคอน | ปุ่มแรก | เลื่อนระหว่างปุ่ม |
| Token ตัวกรอง | chip แรก | เลื่อนระหว่าง chip |

**`CheckboxList` ไม่ใช้ roving tabindex** — checkbox แต่ละตัวเป็น tab stop ของตัวเอง เพราะเลือกได้หลายตัวพร้อมกัน

### 1.3 ⚠️ ห้าม single-character shortcut — เหตุผลเฉพาะภาษาไทย

**SC 2.1.4** กำหนดว่าถ้ามี shortcut ที่เป็นตัวอักษรเดี่ยว ต้องมีวิธีปิด เปลี่ยน หรือจำกัดให้ทำงานเฉพาะเมื่อ focus อยู่

**ระบบนี้เลือกไม่มีเลย** เพราะมีเหตุผลเพิ่มที่ไม่มีในผลิตภัณฑ์ภาษาอังกฤษ

ผู้ใช้ไทยสลับ layout คีย์บอร์ดระหว่างไทยและอังกฤษตลอดเวลา shortcut `s` สำหรับค้นหาจะกลายเป็น `ห` เมื่ออยู่ layout ไทย — ทำให้ shortcut ไม่ทำงานโดยไม่มีคำอธิบาย หรือแย่กว่านั้นคือ**ทำงานโดยที่ผู้ใช้ตั้งใจพิมพ์ตัวอักษร**

**ใช้ modifier combo เท่านั้น** — `Cmd/Ctrl + K` สำหรับค้นหา ซึ่งไม่ขึ้นกับ layout

### 1.4 ⚠️ Thai IME — การตรวจสอบต้องรอ composition จบ

ผู้ใช้ไทยพิมพ์ผ่าน input method ที่ประกอบอักขระหลายตัวเป็นหนึ่งตัว (ท + ี + ่ = ที่) ระหว่างการประกอบ `onChange` จะยิงหลายครั้งด้วยค่าที่ยังไม่สมบูรณ์

**ถ้าตรวจสอบทันทีทุก keystroke** ผู้ใช้จะเห็นข้อความ error กระพริบขึ้นระหว่างพิมพ์คำที่ถูกต้อง

```tsx
const [composing, setComposing] = useState(false);

<input
  onCompositionStart={() => setComposing(true)}
  onCompositionEnd={(e) => { setComposing(false); validate(e.currentTarget.value); }}
  onChange={(e) => { setValue(e.target.value); if (!composing) validate(e.target.value); }}
/>
```

**กฎ: ตรวจสอบตอน `blur` เป็นหลัก และห้ามตรวจระหว่าง composition**

### 1.5 ห้ามมีกับดัก focus

| กฎ | ตาม SC |
|---|---|
| Modal ต้องกัก focus ไว้ข้างใน **แต่ `Esc` ต้องออกได้เสมอ** | 2.1.2 |
| Focus ต้องกลับไปที่ element ที่เปิด modal เมื่อปิด | 2.4.3 |
| `<iframe>` และ embed ต้องออกด้วย `Tab` ได้ | 2.1.2 |
| ห้าม `autofocus` บนหน้าที่โหลดใหม่ | 2.4.3 |

## 2 · Contrast

ค่าครบและคำนวณจริงอยู่ใน [`02-color.md`](02-color.md) — ที่นี่สรุปเฉพาะเกณฑ์และกับดัก

### 2.1 เกณฑ์

| ประเภท | เกณฑ์ | SC |
|---|---|---|
| ตัวอักษรปกติ (< 24px หรือ < 18.66px bold) | **≥ 4.5:1** | 1.4.3 |
| ตัวอักษรใหญ่ (≥ 24px หรือ ≥ 18.66px bold) | **≥ 3:1** | 1.4.3 |
| ขอบ UI component · ไอคอนสื่อความหมาย · focus ring | **≥ 3:1** | 1.4.11 |
| ข้อความ disabled | **ยกเว้น** | 1.4.3 |
| ไอคอนตกแต่ง (มีข้อความข้าง ๆ) | **ยกเว้น** | 1.4.11 |

### 2.2 กับดัก 5 ข้อที่ตรวจแล้วพบในระบบนี้

| ที่มักใช้กัน | วัดได้ | ต้องใช้ |
|---|---|---|
| `neutral-300` เป็นขอบ input | **1.56:1** ❌ | **`neutral-500`** (4.20:1) |
| `neutral-500` เป็นตัวอักษรจาง | **4.20:1** ❌ | **`neutral-600`** (6.05:1) |
| `success-600` + ตัวอักษรขาว | **4.11:1** ❌ | **`success-700`** (5.96:1) |
| `warning-700` เป็นตัวอักษร | **3.75:1** ❌ | **`warning-800`** (5.54:1) |
| `neutral-600` เป็นขอบโหมดมืด | **2.67:1** บน surface ❌ | **`neutral-500`** (3.84:1) |

### 2.3 กฎที่มาจากข้อจำกัดทางกายภาพของสี

| กฎ | เหตุผล |
|---|---|
| **พื้นทองและพื้นเหลืองใช้ตัวอักษร `neutral-950` เท่านั้น** | ตัวอักษรขาวได้ 2.37:1 และ 1.66:1 — สีอิ่มตัวที่ hue 36–48° มี luminance สูงตามธรรมชาติ |
| **`warning-500` เป็น fill-only** | บนพื้นขาว 1.66:1 — ใช้เป็นตัวอักษรหรือไอคอนไม่ได้เลย |
| **`primary-600` ห้ามเป็นตัวอักษรบนพื้นมืด** | 3.86:1 — ใช้ `primary-400` (7.18:1) |
| **โหมดมืดใช้ขั้น 400 สำหรับตัวอักษรและไอคอนทุกสี** | ขั้น 700+ ไม่ผ่านบนพื้นมืดทั้งหมด |

### 2.4 SC 1.4.1 — ห้ามใช้สีเป็นตัวสื่อความหมายเพียงอย่างเดียว

**สำคัญเป็นพิเศษในระบบนี้** เพราะ [`02-color.md` §9](02-color.md) บันทึกว่าทอง (hue 36°) กับเหลือง (hue 48°) ห่างกันเพียง **1.43:1** ทางความสว่าง

| สถานะ | รูปทรง (Lucide) | สี |
|---|---|---|
| สำเร็จ | `circle-check` — วงกลม | `success-700` |
| เตือน | `triangle-alert` — **สามเหลี่ยม** | `warning-800` |
| ผิดพลาด | `circle-x` — วงกลม + กากบาท | `danger-600` |
| ข้อมูล | `info` — วงกลม + i | `primary-600` |

**รูปทรงคือตัวแยกที่แท้จริง ไม่ใช่สี** — และลิงก์ต้องมีขีดใต้ เพราะ contrast ระหว่างลิงก์กับข้อความรอบข้างต่ำกว่า 3:1

## 3 · Focus Ring

### 3.1 สเปก

```css
:where(a, button, input, select, textarea, summary, [tabindex]):focus-visible {
  outline: 2px solid var(--color-focus-ring);
  outline-offset: 2px;
  box-shadow: 0 0 0 2px var(--color-focus-contrast);
  scroll-margin-top:    calc(var(--header-height) + var(--spacing) * 2);
  scroll-margin-bottom: calc(var(--bottom-inset) + var(--spacing) * 2);
}
```

| Token | โหมดสว่าง | โหมดมืด |
|---|---|---|
| `--color-focus-ring` | `primary-600` `#0077C1` | `primary-400` `#50AAE2` |
| `--color-focus-contrast` | `neutral-0` `#FFFFFF` | `neutral-950` `#12141A` |

### 3.2 ทำไม 2 ชั้น

วงแหวนชั้นเดียวสีน้ำเงินจะ **มองไม่เห็นบนปุ่มสีน้ำเงิน** ชั้นในสีตรงข้ามทำให้เห็นได้บนทุกพื้นโดยไม่ต้องมี logic ต่อ component

| พื้น | ชั้นนอก (primary-600) | ชั้นใน (neutral-0) |
|---|---|---|
| พื้นขาว | 4.76:1 ✅ | มองไม่เห็น (ไม่เป็นไร) |
| พื้น `primary-600` ทึบ | มองไม่เห็น | **ตัวคั่นที่ทำให้เห็นชั้นนอก** ✅ |
| พื้นทอง `gold-500` | ✅ | ✅ |
| พื้น `danger-600` | ✅ | ✅ |

### 3.3 กฎที่ต้องบังคับ

| กฎ | เหตุผล |
|---|---|
| **`:focus-visible` เท่านั้น ห้าม `:focus`** | `:focus` ทำให้ผู้ใช้เมาส์เห็นวงแหวนตอนคลิก ซึ่งเป็นสาเหตุที่ทีมมักลบ outline ออกทั้งหมดในที่สุด |
| **ห้าม `outline: none` ทุกกรณี** | เว้นแต่แทนที่ด้วย indicator ที่ผ่าน 3:1 ทันทีในบรรทัดเดียวกัน |
| **ห้าม `overflow: hidden` บน ancestor ของ focusable** | วงแหวนล้น 4px จะถูกตัด — ดู [`05-radius.md` §5](05-radius.md) |
| **`scroll-margin` ทั้งบนและล่าง** | SC 2.4.11 — ดูข้อ 6.1 |

## 4 · Touch Target

### 4.1 ตัวบทที่ถูกต้อง

**SC 2.5.8 Target Size (Minimum), ระดับ AA** — เป้าต้องมีขนาด **≥ 24×24 CSS px หรือ** เข้าข่ายข้อยกเว้น และข้อยกเว้น *Spacing* ใช้กับ **เป้าที่เล็กกว่า 24px เท่านั้น**

> **เป้าที่ 24×24 พอดีผ่านเกณฑ์โดยตรง และไม่มีข้อกำหนดเรื่องระยะห่างระหว่างเป้าเลย**

เป้า 24×24 สองอันวางติดกันโดยไม่มี gap ก็ผ่าน เพราะจุดศูนย์กลางห่างกัน 24px วงกลมรัศมี 12px จึงแตะกันพอดีแต่ไม่ทับ

### 4.2 กฎเดียวที่ต้องทำ

> **ห้ามมีเป้าใดเล็กกว่า 24×24 CSS px**

| Icon | Padding | เป้า | ผล |
|---|---|---|---|
| 16px | `space-1` 4px | 24×24 | ✅ พอดี |
| 16px | `space-0.5` 2px | 20×20 | ❌ |
| 16px | ไม่มี | 16×16 | ❌ |
| 20px | `space-1` 4px | 28×28 | ✅ |
| 24px | ไม่มี | 24×24 | ✅ พอดี |

**Component ที่ต้องตรวจเป็นพิเศษ** — checkbox/radio ที่ตั้งขนาด 16px ตรง ๆ · ปุ่มปิดที่ใส่ padding 2px · ปุ่มจัดการในแถวตารางที่ถูกบีบเพราะแถวสูงจำกัด · chip ตัวกรองบนมือถือ

**ขยายพื้นที่กดได้โดยไม่เปลี่ยนขนาดที่เห็น** ด้วย pseudo-element ตาม [`09-iconography.md` §4](09-iconography.md)

### 4.3 ⚠️ ความเสี่ยงที่ยอมรับไว้

**24×24 เป็นการตัดสินใจของเจ้าของงาน** และผ่าน WCAG 2.2 AA จริง แต่ต่ำกว่าที่ผู้ใช้ไทยคุ้นจาก LINE และ Shopee (44–48px) อย่างมีนัยสำคัญ

**คาดว่าอัตรากดผิดจะสูงขึ้น** โดยเฉพาะ chip ตัวกรองบนมือถือ และกลุ่ม radio/checkbox ในฟอร์มขอสินเชื่อ — ควรวัดจริงหลังปล่อยและทบทวนถ้าข้อมูลบอกว่าเป็นปัญหา

## 5 · ARIA

### 5.1 หลัก: HTML ก่อน ARIA เสมอ

> ARIA ที่ไม่มีก็ดีกว่า ARIA ที่ผิด

| ใช้ | ไม่ใช่ |
|---|---|
| `<button>` | `<div role="button" tabindex="0">` |
| `<a href>` | `<span onclick>` |
| `<input type="checkbox">` | `<div role="checkbox">` |
| `<dialog>` | `<div role="dialog">` |
| `<details>` / `<summary>` | accordion ที่เขียน ARIA เอง |
| `<nav>` `<main>` `<aside>` | `<div role="navigation">` |

### 5.2 Pattern ที่ต้องใช้

| Component | ARIA ที่จำเป็น |
|---|---|
| ปุ่มไอคอนล้วน | `aria-label` บน `<button>` · ไอคอนเป็น `aria-hidden="true"` |
| ปุ่มที่มี state | `aria-pressed` (toggle) · `aria-expanded` (เปิด/ปิด) |
| Modal | `<dialog>` + `aria-labelledby` ชี้ที่หัวข้อ |
| Tabs | `role="tablist"` · `role="tab"` + `aria-selected` · `role="tabpanel"` + `aria-labelledby` |
| Combobox | `role="combobox"` · `aria-expanded` · `aria-controls` · `aria-activedescendant` |
| Input ที่ผิดพลาด | `aria-invalid="true"` · `aria-describedby` ชี้ที่ข้อความ error |
| Input ที่มี helper text | `aria-describedby` |
| ตัวกรองที่เปลี่ยนผลลัพธ์ | `aria-live="polite"` บนตัวนับผลลัพธ์ |
| Toast | `role="status"` (ข้อมูล) · `role="alert"` (error) |
| ตัวบ่งชี้การโหลด | `aria-busy="true"` บน container · `aria-live="polite"` |
| Skeleton | `aria-hidden="true"` + ข้อความ "กำลังโหลด" ใน live region |

### 5.3 SC 4.1.3 Status Messages

การเปลี่ยนแปลงที่ไม่ย้าย focus ต้องประกาศให้ screen reader รู้

| เหตุการณ์ | วิธีประกาศ |
|---|---|
| จำนวนผลการค้นหาเปลี่ยนหลังกรอง | `aria-live="polite"` — "พบ 24 รายการ" |
| เพิ่มสินค้าลงตะกร้าสำเร็จ | `role="status"` |
| บันทึกร่างอัตโนมัติ | `aria-live="polite"` — "บันทึกร่างแล้ว" |
| ฟอร์มส่งไม่สำเร็จ | `role="alert"` + ย้าย focus ไปที่สรุป error |
| อัปโหลดคืบหน้า | `aria-live="polite"` แต่ **throttle** ไม่ประกาศทุก 1% |

### 5.4 ⚠️ SC 2.5.3 Label in Name — ข้อควรระวังกับภาษาไทย

ถ้าปุ่มแสดงข้อความ "ยื่นคำขอสินเชื่อ" แต่ `aria-label` เขียนว่า "Apply for loan" — **ไม่ผ่าน** เพราะชื่อที่โปรแกรมอ่านได้ต้องมีข้อความที่มองเห็นอยู่ด้วย

**กฎ: `aria-label` ต้องเป็นภาษาไทยและต้องมีข้อความที่แสดงอยู่จริงรวมอยู่ด้วย** — เป็นกับดักที่พบบ่อยเมื่อทีมเขียนโค้ดเป็นอังกฤษแต่ UI เป็นไทย

### 5.5 Screen reader ที่ต้องทดสอบ

| ลำดับ | คู่ | เหตุผล |
|---|---|---|
| 1 | **TalkBack + Chrome (Android)** | ผู้ใช้ไทยส่วนใหญ่อยู่บน Android |
| 2 | NVDA + Firefox (Windows) | เดสก์ท็อปที่พบมากที่สุด |
| 3 | VoiceOver + Safari (iOS/macOS) | |

**ทดสอบด้วยเสียงภาษาไทย** ไม่ใช่ภาษาอังกฤษ — และ **หลีกเลี่ยงคำย่อ** เพราะ TTS ไทยอ่านคำย่ออย่าง "ภ.พ.30" และ "มอก." ได้ไม่ดี ให้ใส่คำเต็มใน `aria-label`

## 6 · ⚠️ WCAG 2.2 — เกณฑ์ใหม่ 4 ข้อที่กระทบ SME.GO โดยตรง

เกณฑ์เหล่านี้เพิ่มใน WCAG 2.2 และทีมส่วนใหญ่ยังไม่ได้ตรวจ

### 6.1 SC 2.4.11 Focus Not Obscured (AA)

Element ที่ได้รับ focus **ต้องไม่ถูกบดบัง**โดยเนื้อหาอื่น

**ตัวบทไม่ระบุทิศทาง** — header ค้างที่ด้านบนและแถบนำทางค้างที่ด้านล่างทับ focus ได้เหมือนกัน

```css
:where(a, button, input, select, textarea, summary, [tabindex]) {
  scroll-margin-top:    calc(var(--header-height) + var(--spacing) * 2);
  scroll-margin-bottom: calc(var(--bottom-inset) + var(--spacing) * 2);
}
```

**`--header-height` และ `--bottom-inset` ต้องเป็น token** ถ้าใครแก้ความสูงแถบใน component โดยไม่แก้ token ระบบจะไม่ผ่านทันทีทั้งระบบ — และเป็นความล้มเหลวที่**มองไม่เห็นด้วยตา** ต้องกด Tab ทดสอบ

⚠️ `--bottom-inset` เป็น `calc()` ที่รวม **ทุกแถบที่ยึดก้นจอ** (`--bottom-nav-height` + `--compare-bar-height` + `--action-bar-height`) · แต่ละแถบเขียนเฉพาะตัวแปรของตัวเอง — การเขียนตัวแปรของแถบอื่นทำให้ last-writer-wins และจองพื้นที่ขาด

### 6.2 SC 2.5.7 Dragging Movements (AA)

ทุกอย่างที่ทำได้ด้วยการลาก **ต้องทำได้ด้วยการกดครั้งเดียว**ด้วย

| ที่ SME.GO มี | ต้องมีทางเลือกอะไร |
|---|---|
| ลาก bottom sheet ลงเพื่อปิด | **ปุ่มปิด** ที่มองเห็นได้ + `Esc` |
| Slider เลือกช่วงราคา | **ช่องกรอกตัวเลข** ต้นทาง-ปลายทาง + ปุ่มลูกศร |
| ปัดเพื่อลบรายการ | **ปุ่มลบ** ที่มองเห็นได้ |
| ลากจัดลำดับรายการโปรด | **ปุ่มเลื่อนขึ้น/ลง** |
| Carousel ที่ปัดได้ | **ปุ่มก่อนหน้า/ถัดไป** |

**Slider ช่วงราคาเป็นจุดที่ต้องระวังที่สุด** เพราะเป็นตัวกรองหลักของ marketplace และมักถูกทำเป็นลากเท่านั้น

### 6.3 SC 3.3.7 Redundant Entry (A)

ข้อมูลที่ผู้ใช้กรอกแล้วในขั้นตอนเดียวกัน **ห้ามให้กรอกซ้ำ** — ต้องเติมให้อัตโนมัติหรือให้เลือกจากที่กรอกไว้

**กระทบตรงกับฟอร์มขอสินเชื่อและลงทะเบียนหลายขั้นตอนของ SME.GO**

| ห้าม | ต้องทำ |
|---|---|
| ขอเลขนิติบุคคลซ้ำในขั้นที่ 3 หลังกรอกในขั้นที่ 1 | เติมอัตโนมัติ แสดงแบบอ่านได้พร้อมปุ่มแก้ไข |
| ขอที่อยู่จัดส่งซ้ำกับที่อยู่จดทะเบียน | checkbox "ใช้ที่อยู่เดียวกัน" |
| ให้กรอกอีเมลสองครั้งเพื่อยืนยัน | กรอกครั้งเดียว + ให้มองเห็นสิ่งที่พิมพ์ได้ |

**ยกเว้น:** การกรอกซ้ำที่จำเป็นเพื่อความปลอดภัย เช่น ยืนยันรหัสผ่านใหม่

### 6.4 ⚠️ SC 3.3.8 Accessible Authentication (Minimum) (AA)

ขั้นตอนการเข้าสู่ระบบ **ห้ามพึ่งการทดสอบการทำงานของสมอง** (cognitive function test) เว้นแต่มีทางเลือกอื่น

**นี่คือข้อที่แพลตฟอร์มภาครัฐไทยไม่ผ่านบ่อยที่สุด**

| ห้าม | เหตุผล |
|---|---|
| **บล็อกการวาง (paste) ในช่อง OTP** | บังคับให้ผู้ใช้จำตัวเลข 6 หลัก = cognitive function test |
| **บล็อกการวางในช่องรหัสผ่าน** | ทำให้ใช้ password manager ไม่ได้ |
| CAPTCHA แบบไขปัญหาโดยไม่มีทางเลือก | |
| ให้จำรหัสจาก SMS แล้วพิมพ์ในหน้าอื่นที่เห็นไม่ได้ | |

| ต้องทำ |
|---|
| **อนุญาตให้วางในทุกช่อง** รวมถึง OTP และรหัสผ่าน |
| `autocomplete="one-time-code"` ในช่อง OTP เพื่อให้ระบบเติมอัตโนมัติ |
| `autocomplete="current-password"` / `"new-password"` |
| มีปุ่มแสดง/ซ่อนรหัสผ่าน |
| ThaID และการเข้าสู่ระบบด้วยผู้ให้บริการภายนอกช่วยข้อนี้ได้ แต่**ต้องมีทางเลือกที่ไม่ต้องใช้แอปด้วย** |

**⚠️ ห้ามใช้ช่อง OTP แบบแยกกล่องละหลัก** ที่ตัด paste — ถ้าใช้ต้องรองรับการวางเลขทั้งชุดแล้วกระจายลงกล่องเอง

### 7.1 ⚠️ SC 1.4.12 Text Spacing — ความตึงกับข้อ 03

SC 1.4.12 กำหนดว่าเนื้อหาต้องยังใช้งานได้เมื่อ**ผู้ใช้บังคับ** ค่าเหล่านี้

| คุณสมบัติ | ค่าที่ต้องรองรับ | ระบบนี้ |
|---|---|---|
| `line-height` | ≥ 1.5 เท่าของขนาดตัวอักษร | **1.750 อยู่แล้ว** ✅ |
| `letter-spacing` | ≥ 0.12em | ต้องไม่ตัดเนื้อหา |
| `word-spacing` | ≥ 0.16em | ต้องไม่ตัดเนื้อหา |
| ระยะย่อหน้า | ≥ 2em | ต้องไม่ตัดเนื้อหา |

**ความตึง:** [`03-typography.md` §5](03-typography.md) ห้ามใส่ `letter-spacing` กับข้อความไทย

**การแก้ไข — ไม่ขัดกันจริง** ข้อ 03 ห้าม **เราเอง** ใส่ `letter-spacing` ส่วน SC 1.4.12 กำหนดว่า **ผู้ใช้** ต้องบังคับได้โดยไม่มีเนื้อหาหาย

**ผลที่ตามมาเป็นกฎที่ต้องทำ**

| กฎ | เหตุผล |
|---|---|
| **ห้าม `letter-spacing` แบบมี `!important`** | จะบล็อก user stylesheet |
| **ห้ามตั้งความสูงคงที่บน container ที่มีข้อความ** | ใช้ `min-height` ไม่ใช่ `height` |
| **ห้าม `overflow: hidden` บนกล่องข้อความ** | ข้อความที่ขยายจะถูกตัด |
| **ปุ่มและ chip ต้องยืดตามเนื้อหา** | ห้ามตั้งความกว้างคงที่ |
| **ทดสอบด้วย bookmarklet ที่บังคับค่าทั้ง 4** | เป็นการทดสอบเดียวที่จับข้อนี้ได้ |

**หมายเหตุ:** เมื่อผู้ใช้บังคับ `letter-spacing: 0.12em` กับข้อความไทย สระและวรรณยุกต์จะดูหลุดจากพยัญชนะ — **น่าเกลียดแต่ไม่ใช่การไม่ผ่าน** เพราะเกณฑ์วัดว่าเนื้อหาหายหรือไม่ ไม่ใช่ว่าสวยหรือไม่

### 7.2 SC 1.4.13 Content on Hover or Focus

Tooltip และ popover ที่เปิดด้วย hover หรือ focus ต้องมีคุณสมบัติ 3 ข้อ

| คุณสมบัติ | ความหมาย |
|---|---|
| **Dismissable** | ปิดด้วย `Esc` ได้ โดยไม่ต้องย้ายเมาส์หรือ focus |
| **Hoverable** | เลื่อนเมาส์เข้าไปใน tooltip ได้โดยที่มันไม่หาย |
| **Persistent** | อยู่จนกว่าจะ hover ออก · focus ออก · หรือกด Esc — **ห้ามหายเองตามเวลา** |

**ห้ามใส่ `setTimeout` ให้ tooltip หายเอง** — เป็นความผิดพลาดที่พบบ่อยที่สุดของข้อนี้

## 8 · เกณฑ์การ merge / Definition of Done

Component ถือว่าเสร็จเมื่อผ่านทุกข้อ

### 8.1 ตรวจอัตโนมัติได้

- [ ] `axe-core` ไม่พบ violation
- [ ] ทุกคู่สีมีค่า contrast ที่คำนวณแล้วในเอกสาร component
- [ ] ไม่มี `font-size` token ต่ำกว่า 13px
- [ ] ไม่มีเป้าที่กดได้เล็กกว่า 24×24
- [ ] ไม่มี `outline: none` ที่ไม่มี indicator แทน
- [ ] ไม่มี `!important` (ยกเว้น block `prefers-reduced-motion`)
- [ ] ไม่มี `tabindex` ค่าบวก
- [ ] ไม่มี `import` จาก `lucide-react` โดยตรง
- [ ] ไม่มี `overflow: hidden` บน ancestor ของ focusable
- [ ] ไม่มีค่า spacing/radius นอก scale และไม่มี arbitrary value
- [ ] ไม่มีอักขระเลขไทย U+0E50–U+0E59 ในข้อมูลที่เข้า component ตาราง/ราคา
- [ ] ไม่มี `letter-spacing` หรือ `text-transform` บน element ที่มีข้อความไทย
- [ ] ไม่มี `font-style: italic`

### 8.2 ต้องตรวจด้วยมือ

- [ ] ใช้งานครบด้วยคีย์บอร์ดล้วน ไม่มีกับดัก focus
- [ ] Focus ring มองเห็นได้ทั้ง **โหมดสว่าง โหมดมืด และบนพื้นสีอิ่มตัว**
- [ ] กด Tab ผ่านทั้งหน้าแล้ว focus **ไม่ถูก header หรือแถบล่างทับ**
- [ ] ทดสอบที่ **320px** ไม่มี horizontal scroll
- [ ] ทดสอบที่ตัวอักษร **200%** ไม่มีเนื้อหาถูกตัด
- [ ] ทดสอบด้วย bookmarklet **Text Spacing** (SC 1.4.12) ทั้ง 4 ค่า
- [ ] เปิด `prefers-reduced-motion` แล้วไม่มีการเคลื่อนที่เหลือ (progress/spinner ยกเว้น)
- [ ] ทุกอย่างที่ลากได้ **มีทางเลือกกดครั้งเดียว** (SC 2.5.7)
- [ ] **วางลงช่อง OTP และรหัสผ่านได้** (SC 3.3.8)
- [ ] ไม่มีการขอข้อมูลซ้ำในขั้นตอนเดียวกัน (SC 3.3.7)
- [ ] Tooltip ปิดด้วย Esc ได้ · hover เข้าได้ · **ไม่หายเอง**
- [ ] `aria-label` เป็นภาษาไทยและมีข้อความที่แสดงอยู่รวมด้วย (SC 2.5.3)
- [ ] การตรวจสอบฟอร์มไม่ยิงระหว่าง Thai IME composition
- [ ] TalkBack + Chrome บน Android ด้วยเสียงไทย อ่านได้ถูกต้อง
- [ ] สถานะทุกอันมีทั้ง**รูปทรงและข้อความ** ไม่ใช่แค่สี

## 10 · ความเสี่ยงที่ยังอยู่

## 🎨 Designer Notes

- **ออกแบบสถานะ focus ไปด้วยทุก component** ไม่ใช่ปล่อยให้นักพัฒนาเดา — และตรวจว่าเห็นได้บนพื้นสีอิ่มตัวด้วย ไม่ใช่แค่พื้นขาว
- **ทุกอย่างที่ลากได้ต้องมีปุ่ม** slider ช่วงราคาต้องมีช่องกรอกตัวเลข · bottom sheet ต้องมีปุ่มปิด (SC 2.5.7)
- **สถานะต้องต่างกันที่รูปทรง** เตือน = สามเหลี่ยม ไม่ใช่วงกลมสีเหลือง
- **Tooltip ห้ามหายเอง** ต้องอยู่จนกด Esc หรือ hover ออก
- **frame 320px ต้องมีทุกหน้า** เป็นข้อกำหนด SC 1.4.10 ไม่ใช่ทางเลือก
- **ฟอร์มหลายขั้นตอนต้องแสดงข้อมูลที่กรอกแล้วแบบอ่านได้** ไม่ใช่ให้กรอกซ้ำ (SC 3.3.7)
- **ช่อง OTP ต้องรองรับการวาง** ถ้าออกแบบเป็นกล่องแยกหลัก ต้องรองรับวางทั้งชุด (SC 3.3.8)
- **ปุ่มและ chip ต้องยืดตามเนื้อหา** ห้ามตั้งความกว้างคงที่ เพราะ SC 1.4.12 ให้ผู้ใช้ขยายระยะตัวอักษรได้

## 💻 Developer Notes

- **`:focus-visible` เท่านั้น** และห้าม `outline: none` ที่ไม่มี indicator แทนในบรรทัดเดียวกัน
- **`--header-height` และ `--bottom-inset` เป็น token ที่รับน้ำหนัก conformance** ห้าม hardcode · แถบแต่ละตัวเขียนได้เฉพาะความสูงของตัวเอง
- **อนุญาตให้วางในทุกช่อง** รวม OTP และรหัสผ่าน · ใส่ `autocomplete="one-time-code"` · ห้าม `onPaste={e => e.preventDefault()}`
- **ห้าม single-character shortcut** ใช้ `Cmd/Ctrl + K` — layout ไทยทำให้ shortcut ตัวอักษรเดี่ยวใช้ไม่ได้และอาจทำงานตอนผู้ใช้พิมพ์
- **ห้ามตรวจสอบฟอร์มระหว่าง Thai IME composition** ใช้ `onCompositionEnd` และ `blur`
- **`aria-label` เป็นภาษาไทยและต้องมีข้อความที่แสดงอยู่รวมด้วย** (SC 2.5.3)
- **`role="alert"` เฉพาะ error** ข้อมูลทั่วไปใช้ `role="status"` / `aria-live="polite"`
- **Throttle `aria-live`** อย่าประกาศความคืบหน้าทุก 1%
- **ห้าม `setTimeout` ให้ tooltip หายเอง** (SC 1.4.13)
- **`min-height` ไม่ใช่ `height` บน container ที่มีข้อความ** เพื่อให้ผ่าน SC 1.4.12
- **หลีกเลี่ยงคำย่อใน `aria-label`** TTS ไทยอ่าน "ภ.พ.30" และ "มอก." ได้ไม่ดี ใส่คำเต็ม
- **ทดสอบ TalkBack + Chrome บน Android ด้วยเสียงไทยเป็นลำดับแรก** เพราะเป็นสภาพแวดล้อมของผู้ใช้กลุ่มหลัก

## 🧠 Decision Rationale

### ทำไมเน้นเกณฑ์ใหม่ 4 ข้อของ WCAG 2.2 เป็นพิเศษ
เพราะทีมส่วนใหญ่ยังตรวจตามเช็กลิสต์ของ WCAG 2.1 และ 4 ข้อนี้กระทบ SME.GO ตรงจุดที่สุด

**SC 3.3.8** เป็นข้อที่แพลตฟอร์มภาครัฐไทยไม่ผ่านบ่อยที่สุด เพราะการบล็อกการวางในช่อง OTP ถูกมองว่าเป็นมาตรการความปลอดภัย แต่ในความจริงมันบังคับให้ผู้ใช้จำตัวเลข 6 หลัก ซึ่งตัวบทนับเป็น cognitive function test ตรง ๆ และเป็นอุปสรรคจริงกับผู้ใช้ที่มีปัญหาด้านความจำหรือใช้ password manager

**SC 2.5.7** กระทบ slider ช่วงราคา ซึ่งเป็นตัวกรองหลักของทุก marketplace และมักถูกทำเป็นลากเท่านั้น

**SC 3.3.7** กระทบฟอร์มขอสินเชื่อและลงทะเบียนหลายขั้นตอน ซึ่งเป็นแกนของผลิตภัณฑ์นี้

**SC 2.4.11** ล้มเหลวแบบมองไม่เห็นด้วยตา ต้องกด Tab ทดสอบเท่านั้น

### ทำไม SC 1.4.12 ไม่ขัดกับข้อ 03 จริง
เพราะเป็นเรื่องคนละฝ่าย ข้อ 03 ห้าม **นักออกแบบและนักพัฒนา** ใส่ `letter-spacing` กับข้อความไทย เพราะจะทำให้สระและวรรณยุกต์หลุดจากพยัญชนะ ส่วน SC 1.4.12 กำหนดว่า **ผู้ใช้** ต้องบังคับค่านั้นได้เองโดยเนื้อหาไม่หาย

ผลที่ตามมาคือกฎเชิงเทคนิคที่วัดได้ — ห้าม `!important` บน `letter-spacing` · ใช้ `min-height` ไม่ใช่ `height` · ห้าม `overflow: hidden` บนกล่องข้อความ · ปุ่มยืดตามเนื้อหา

และการยอมรับตรง ๆ ว่าผลลัพธ์จะ **น่าเกลียดแต่ไม่ผิดเกณฑ์** สำคัญ เพราะไม่เช่นนั้นจะมีคนพยายาม "แก้" ด้วยการบล็อก user stylesheet ซึ่งจะทำให้ไม่ผ่านจริง

### ทำไมห้าม single-character shortcut แทนที่จะทำให้ปิดได้
SC 2.1.4 ยอมให้มี shortcut ตัวอักษรเดี่ยวได้ถ้ามีวิธีปิดหรือเปลี่ยน — ระบบนี้เลือกไม่มีเลย เพราะบริบทภาษาไทยเพิ่มปัญหาที่ตัวบทไม่ได้ครอบคลุม

ผู้ใช้ไทยสลับ layout คีย์บอร์ดตลอดเวลา `s` กลายเป็น `ห` เมื่ออยู่ layout ไทย ทำให้ shortcut ไม่ทำงานโดยไม่มีคำอธิบาย และในทางกลับกัน การกดปุ่มที่ตั้งใจพิมพ์ตัวอักษรไทยอาจไปกระตุ้น shortcut ที่ผูกกับตัวอักษรละตินตำแหน่งเดียวกัน

การใช้ modifier combo แก้ทั้งสองปัญหาโดยไม่ต้องมีหน้าตั้งค่าเพิ่ม

### ทำไมต้องเขียนเรื่อง Thai IME
เพราะเป็นปัญหาที่ **ไม่ปรากฏเลยเมื่อทดสอบด้วยภาษาอังกฤษ** และปรากฏทันทีกับผู้ใช้จริง

การตรวจสอบที่ยิงทุก keystroke จะเห็นค่ากลางที่ยังประกอบไม่เสร็จ ทำให้ข้อความ error กระพริบขึ้นระหว่างที่ผู้ใช้พิมพ์คำที่ถูกต้อง — ซึ่งบั่นทอนความมั่นใจในระบบ และขัดกับหลัก "ความน่าเชื่อถือมาก่อนความสวยงาม" ในข้อ 01 โดยตรง

### ทำไมทำการตรวจความสอดคล้องข้าม 10 ข้อ
เพราะชั้น Foundation ที่ขัดกันเองจะถูกละเมิดโดยจำเป็น — นักพัฒนาที่เจอกฎสองข้อที่ทำตามพร้อมกันไม่ได้จะเลือกข้อหนึ่งโดยไม่บันทึก และการเลือกนั้นจะกระจายไปทั่ว codebase อย่างไม่สม่ำเสมอ

ทั้ง 3 ความขัดแย้งที่พบเกิดจากการตัดสินใจที่ **ถูกทั้งคู่** (มุมโค้ง vs focus ring · ห้าม `!important` vs ต้องชนะ inline style ของ Framer · ห้าม letter-spacing vs ต้องให้ผู้ใช้บังคับได้) การเขียนทางแก้ไว้ชัดทำให้ไม่มีใครต้องตัดสินใจเองตอน implement

และตาราง §9.3 มีไว้เพื่อกันความล้มเหลวที่แย่ที่สุด — คนแก้ `--header-height` ใน component โดยไม่รู้ว่า `scroll-margin` ของทุก focusable ในระบบอ้างค่านั้นเพื่อผ่าน SC 2.4.11

### ทำไมบันทึกความเสี่ยงที่ยังอยู่ไว้ในเอกสาร
เพราะทั้ง 7 ข้อเป็นเรื่องที่ **รู้อยู่แล้วและเลือกยอมรับ** ไม่ใช่สิ่งที่มองข้าม

การเขียนไว้ทำให้สองอย่างเกิดขึ้น — คนที่มาทีหลังไม่ต้องค้นพบซ้ำและไม่คิดว่าเป็นความบกพร่องที่ลืม และเมื่อมีข้อมูลจริงหลังปล่อย (เช่นอัตรากดผิดที่ chip ตัวกรอง) จะมีที่ให้กลับมาทบทวนพร้อมบริบทว่าตอนตัดสินใจคิดอะไรอยู่
