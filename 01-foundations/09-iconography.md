# 09 · Iconography / ระบบไอคอน

**SME.GO Marketplace** · Foundation Layer · WCAG 2.2 AA

---

## ภาพรวม / Overview

**Lucide เป็นไลบรารีเดียวของระบบ** ไม่ผสมกับไลบรารีอื่น เพราะไอคอนจากสองไลบรารีจะมีน้ำหนักเส้น ตาราง และการจบมุมต่างกัน ซึ่งเป็นจุดที่คนสังเกตได้เร็วที่สุดว่า design system ไม่เรียบร้อย

Lucide วาดบนตาราง **24px** ด้วย **stroke-width 2** เป็นค่าเริ่มต้น — ระบบนี้**ไม่ใช้ค่าเริ่มต้นนั้นทุกขนาด** และเหตุผลอยู่ในข้อ 2

---

## 1 · ตารางขนาดและ stroke

**stroke ผูกกับขนาดโดยบังคับ** — ไม่ใช่สองตัวเลือกที่เลือกอิสระ

| Size | Stroke | ใช้กับอะไร |
|---|---|---|
| **16px** | **1.5** | ไอคอนในปุ่ม · metadata · ไอคอนในตาราง · chip |
| **20px** | **1.75** | ไอคอนข้างเนื้อหาหลัก · รายการในเมนู · ไอคอนใน input |
| **24px** | **2** | ไอคอนนำทาง · ปุ่มไอคอนใน toolbar · หัวข้อ section |
| **32px** | **2.5** | ไอคอนหมวดหมู่ · ไอคอนบน card ใหญ่ |
| **48px** | **2.5** | empty state · ไอคอนแสดงสถานะเต็มหน้า |

**บังคับผ่านโครงสร้าง ไม่ใช่ความจำ** — `size` prop ของ Icon wrapper กำหนด stroke ให้เอง และ **`import { X } from 'lucide-react'` ถูกห้ามด้วย lint**

## 2 · ทำไม stroke ต้องเลื่อนตามขนาด

### 2.1 ปัญหาของ stroke คงที่

Lucide วาดบนตาราง 24px ด้วย stroke 2 — ที่ขนาดนั้น เส้นกินพื้นที่ 2/24 = **8.33%** ของกล่องไอคอน

ถ้าใช้ stroke 2 ทุกขนาด สัดส่วนจะเปลี่ยนไปมาก

| Size | stroke 2 | สัดส่วนของกล่อง |
|---|---|---|
| 16px | 2 | **12.50%** |
| 24px | 2 | 8.33% |
| 48px | 2 | **4.17%** |

**ช่วงห่างถึง 3 เท่า** — ไอคอน 16px จะดูหนากว่าไอคอน 48px อย่างชัดเจน และหนักกว่าตัวอักษร `label` 13px ที่วางข้างกัน

### 2.2 สัดส่วนที่ระบบนี้ได้

| Size | Stroke | สัดส่วน | ต่างจากค่าอ้างอิง 8.33% |
|---|---|---|---|
| 16px | 1.5 | **9.38%** | +1.05 จุด — **หนักกว่าโดยตั้งใจ** |
| 20px | 1.75 | 8.75% | +0.42 จุด |
| **24px** | **2** | **8.33%** | ค่าอ้างอิง (ค่าเริ่มต้นของ Lucide) |
| 32px | 2.5 | 7.81% | −0.52 จุด |
| 48px | 2.5 | **5.21%** | −3.12 จุด — **บางกว่าโดยตั้งใจ** |

**ช่วงห่าง 1.8 เท่า** เทียบกับ 3 เท่าของ stroke คงที่ — สม่ำเสมอกว่าอย่างวัดได้

### 2.3 ทำไมไม่ทำให้สัดส่วนคงที่เป๊ะ

สัดส่วนคงที่ 8.33% จะต้องใช้ stroke 1.33 ที่ 16px และ 4 ที่ 48px

**ที่ 16px** — stroke 1.33 บนจอ 1× DPI (ซึ่งยังมีในกลุ่มอุปกรณ์เป้าหมาย) จะถูกปัดเป็นเส้นบางกว่า 1px จริง ทำให้ไอคอนซีดจนหาย และ**เสี่ยงไม่ผ่านเกณฑ์ 3:1** จึงเลือกให้หนากว่าสัดส่วนที่ควรเป็นเล็กน้อย

**ที่ 48px** — stroke 4 ตามสัดส่วนจะทำให้ไอคอนดูเป็นภาพประกอบหนา ๆ ไม่ใช่ไอคอน เพราะที่ขนาดใหญ่ตาเริ่มอ่านไอคอนเป็นรูปทรง ไม่ใช่สัญลักษณ์ จึงเลือกให้บางกว่าสัดส่วน

**สรุป:** ตารางนี้เป็นการประนีประนอมที่ตั้งใจ ไม่ใช่สูตรคณิตศาสตร์ล้วน

## 3 · การจับคู่กับตัวอักษร

**เกณฑ์: ขนาดไอคอนเลือกจาก `font-size` ไม่ใช่จาก `line-height`**

| Text style | font-size | Icon | สัดส่วน |
|---|---|---|---|
| `caption` · `label` | 13px | **16px** | 1.23× |
| `button` · `body-sm` · `code` | 14px | **16px** | 1.14× |
| `body` | 16px | **20px** | 1.25× |
| `body-lg` | 18px | **20px** | 1.11× |
| `subtitle` | 20px | **24px** | 1.20× |
| `title` | 24px | **24px** | 1.00× |
| `heading-sm` | 28px | **32px** | 1.14× |
| `heading-lg` | 32px | **32px** | 1.00× |

**สัดส่วนลดลงเมื่อขนาดใหญ่ขึ้น** — ที่ขนาดเล็กไอคอนต้องใหญ่กว่าตัวอักษรราว 20% เพื่อให้มีน้ำหนักเท่ากันทางสายตา แต่ที่ขนาดใหญ่ 1.0× ก็พอ

### 3.1 📌 แก้ข้อความในข้อ 04

ข้อ 04 §6 เขียนว่า *"ไอคอน 20px วางข้างข้อความ `label` (line-height 20px) จะสูงเท่ากันพอดี"* ซึ่ง **ถูกในเชิงกลไกการจัดแนว แต่ให้คำแนะนำขนาดที่ผิด**

การที่กล่องไอคอนเท่ากับกล่องบรรทัดทำให้ `align-items: center` ทำงานได้โดยไม่ต้องปรับ — **แต่ไอคอน 20px ข้างตัวอักษร 13px นั้นใหญ่เกินไปทางสายตา** (1.54×)

**ค่าที่ถูกคือ 16px** (1.23×) ตามตารางในข้อ 3 — การจัดแนวยังทำงานได้ด้วย `inline-flex` + `align-items: center` ซึ่งไม่ต้องให้ขนาดไอคอนเท่ากล่องบรรทัด

### 3.2 ⚠️ การจัดแนวกับข้อความไทย

อักษรไทยซ้อนสระและวรรณยุกต์ **เหนือ**พยัญชนะ ทำให้หมึกกินพื้นที่ส่วนบนของกล่องบรรทัดมากกว่าอักษรละติน

ผลคือ **ตัวพยัญชนะ — ซึ่งเป็นส่วนที่ตาอ่านว่าเป็น "ตัวอักษร" — อยู่ค่อนไปทางล่างของกล่องบรรทัด**

เมื่อจัดไอคอนให้อยู่กลางกล่องบรรทัดด้วย `align-items: center` ไอคอนจะดู **สูงกว่า**ตัวพยัญชนะเล็กน้อย

| ขนาดข้อความ | ผลที่เห็น | ทำอย่างไร |
|---|---|---|
| `caption` – `body` (13–16px) | ต่างน้อยมาก | ใช้ `align-items: center` ไม่ต้องปรับ |
| `subtitle` – `title` (20–24px) | เริ่มเห็น | ใช้ `align-items: center` — ปรับได้ถ้าจำเป็น |
| `display-*` (36–48px) | เห็นชัด | ปรับลง **2px** ตามข้อยกเว้นที่ข้อ 04 อนุญาตสำหรับการจัดแนวเชิงสายตา |

**ห้ามใช้ค่านอกเหนือจาก 2px** ถ้ารู้สึกว่าต้องใช้ 1px หรือ 3px แปลว่าเลือกขนาดไอคอนผิด ให้กลับไปดูตารางข้อ 3

## 4 · Touch target

ไอคอนที่กดได้ต้องมีขนาดเป้ารวม **≥ 24×24 CSS px** ตามข้อ 16 ของสถาปัตยกรรม

| Icon | Padding ที่ต้องมี | ขนาดเป้า | ผล |
|---|---|---|---|
| 16px | `space-1` **4px** รอบด้าน | 24×24 | ✅ พอดี |
| 16px | `space-0.5` 2px | 20×20 | ❌ **ต่ำกว่าเกณฑ์** |
| 16px | ไม่มี padding | 16×16 | ❌ **ต่ำกว่าเกณฑ์** |
| 20px | `space-1` 4px | 28×28 | ✅ |
| 24px | `space-1` 4px | 32×32 | ✅ |
| 24px | ไม่มี padding | 24×24 | ✅ พอดี |

**กฎ: ไอคอน 16px ที่กดได้ต้องมี `space-1` เป็นขั้นต่ำ** — และตามที่แก้ไว้ในข้อ 04 §7 เป้าที่ ≥24×24 ผ่าน SC 2.5.8 โดยตรง ไม่ต้องตรวจระยะห่างระหว่างเป้า

**พื้นที่กดขยายได้โดยไม่เปลี่ยนขนาดที่เห็น** — ใช้ pseudo-element ถ้า layout ไม่ให้เพิ่ม padding

```css
.icon-button-tight {
  position: relative;
}
.icon-button-tight::before {
  content: "";
  position: absolute;
  inset: 50% auto auto 50%;
  translate: -50% -50%;
  width: max(100%, 1.5rem);    /* 24px */
  height: max(100%, 1.5rem);
}
```

|---|---|---|
| 16px | 3:1 | **≥ 4.5:1** |
| 20px | 3:1 | ≥ 4.5:1 |
| 24px+ | 3:1 | 3:1 |

## 6 · Accessibility ของไอคอน

### 6.1 ไอคอนตกแต่ง vs ไอคอนสื่อความหมาย

| ประเภท | ตัวอย่าง | ต้องทำอะไร |
|---|---|---|
| **ตกแต่ง** — มีข้อความข้าง ๆ อยู่แล้ว | ไอคอนถุงตะกร้า + คำว่า "ตะกร้า" | `aria-hidden="true"` · ไม่ต้องมี label · ยกเว้นจาก 1.4.11 |
| **สื่อความหมาย** — เป็นข้อมูลเดียวที่มี | ไอคอนเครื่องหมายถูกในตารางสถานะ | `role="img"` + `aria-label` · **ต้องผ่าน 3:1** |
| **ปุ่มไอคอนล้วน** | ปุ่มปิด modal | `aria-label` บน `<button>` · ไอคอนเป็น `aria-hidden` |

### 6.2 ปุ่มไอคอนล้วนใช้ได้กับ 5 ไอคอนเท่านั้น

ข้อ 01 กำหนดหลัก *"ชัดเจนกว่าฉลาด"* — ไอคอนต้องมี label กำกับ **ยกเว้นไอคอนที่เป็นมาตรฐานสากลจริง**

| ✅ ใช้ปุ่มไอคอนล้วนได้ | Lucide |
|---|---|
| ค้นหา | `search` |
| ปิด | `x` |
| ย้อนกลับ | `arrow-left` / `chevron-left` |
| เมนู | `menu` |
| เพิ่มเติม | `more-vertical` / `more-horizontal` |

**นอกจาก 5 ตัวนี้ต้องมีข้อความกำกับ** — โดยเฉพาะไอคอนที่เกี่ยวกับเอกสาร การเงิน และการรับรอง ซึ่งเป็นแกนของ SME.GO และไม่มีสัญลักษณ์ที่ผู้ใช้เข้าใจตรงกัน

**และแม้ใน 5 ตัวนั้นก็ยังต้องมี `aria-label`** เพราะ screen reader อ่าน SVG ไม่ได้

### 6.3 ห้ามใช้สีเป็นตัวสื่อความหมายเพียงอย่างเดียว

ตาม SC 1.4.1 — ไอคอนสถานะต้องต่างกันที่ **รูปทรง** ไม่ใช่แค่สี

| สถานะ | Lucide | ทำไมรูปทรงต่างกัน |
|---|---|---|
| สำเร็จ | `circle-check` | วงกลม + เครื่องหมายถูก |
| เตือน | `triangle-alert` | **สามเหลี่ยม** |
| ผิดพลาด | `circle-x` | วงกลม + กากบาท |
| ข้อมูล | `info` | วงกลม + i |

**สามเหลี่ยมของ warning สำคัญเป็นพิเศษ** เพราะข้อ 02 บันทึกไว้ว่าทองกับเหลืองห่างกันเพียง 1.43:1 ทางความสว่าง — รูปทรงจึงเป็นตัวแยกที่แท้จริง ไม่ใช่สี

## 7 · สเปกของ Icon wrapper

```tsx
type IconSize = 16 | 20 | 24 | 32 | 48;

const STROKE: Record<IconSize, number> = {
  16: 1.5,
  20: 1.75,
  24: 2,
  32: 2.5,
  48: 2.5,
};

interface IconProps {
  name: LucideIconName;
  size?: IconSize;              // ค่าเริ่มต้น 20
  label?: string;               // มี = สื่อความหมาย · ไม่มี = ตกแต่ง
  className?: string;
}

export function Icon({ name, size = 20, label, className }: IconProps) {
  const Glyph = registry[name];
  return (
    <Glyph
      width={size}
      height={size}
      strokeWidth={STROKE[size]}       // ← ผูกกับขนาด ไม่ให้ override
      aria-hidden={label ? undefined : true}
      role={label ? "img" : undefined}
      aria-label={label}
      focusable="false"
      className={className}
    />
  );
}
```

**สิ่งที่ API นี้บังคับโดยโครงสร้าง**

| กฎ | บังคับอย่างไร |
|---|---|
| stroke ต้องตรงกับขนาด | `strokeWidth` มาจาก `STROKE[size]` — **ไม่มี prop ให้ override** |
| ขนาดต้องอยู่ใน 5 ค่า | TypeScript union type — ค่าอื่น compile ไม่ผ่าน |
| ไอคอนตกแต่งต้องซ่อนจาก screen reader | ไม่ส่ง `label` = ได้ `aria-hidden` อัตโนมัติ |
| ไอคอนสื่อความหมายต้องมี label | ส่ง `label` = ได้ `role="img"` + `aria-label` พร้อมกัน |
| SVG ไม่ติด tab order ใน IE/Edge เก่า | `focusable="false"` |

**ESLint rule ที่ต้องมี**

```js
"no-restricted-imports": ["error", {
  paths: [{
    name: "lucide-react",
    message: "ใช้ <Icon name=\"...\" size={20} /> เท่านั้น — stroke ต้องผูกกับขนาด ดูข้อ 09"
  }]
}]
```

## 8 · สัญญาการวาดไอคอนเพิ่ม

**Lucide ไม่มีไอคอนสำหรับสิ่งที่ SME.GO เป็นเรื่องเกี่ยวกับจริง ๆ** — ไม่มี ThaID ไม่มี PromptPay ไม่มีใบกำกับภาษีอิเล็กทรอนิกส์ ไม่มีการจดทะเบียน DBD

ชั้นนี้**ไม่วาดไอคอนใหม่** แต่กำหนดสัญญาไว้ เพื่อให้ไอคอนที่วาดในเดือนที่หกยังมีน้ำหนักแยกจาก Lucide ไม่ออก

### 8.1 สัญญาการวาด

| ข้อกำหนด | ค่า |
|---|---|
| Artboard | **24 × 24** |
| พื้นที่วาดจริง (live area) | **20 × 20** — เว้นขอบ 2px ทุกด้าน |
| Stroke | **2** (ที่ artboard 24px) |
| Stroke cap | `round` |
| Stroke join | `round` |
| Fill | **ไม่มี** — เส้นเท่านั้น |
| Path | **compound path เดียว** ถ้าทำได้ |
| การจัดแนว | ทุกจุดอยู่บนตาราง 1px ที่ขนาด 24px |
| `stroke` attribute | `currentColor` — **ห้าม hardcode สี** |
| `viewBox` | `0 0 24 24` |
| ความกว้างเส้นในไฟล์ | ต้องเป็น `stroke-width="2"` เพื่อให้ wrapper scale ได้ |

**เหตุผลที่ต้องเป็น 2 ที่ 24px** — wrapper คำนวณ stroke จากขนาด ถ้าไอคอนที่วาดเองใช้ค่าอื่นเป็นฐาน การ scale จะไม่ตรงกับ Lucide

## 🎨 Designer Notes

- **stroke ผูกกับขนาด ห้ามเลือกอิสระ** 16/1.5 · 20/1.75 · 24/2 · 32/2.5 · 48/2.5 — ถ้าเห็น 16px stroke 2 ในไฟล์ นั่นคือ Lucide default ที่ยังไม่ปรับ
- **เลือกขนาดไอคอนจาก font-size ไม่ใช่ line-height** — ตัวอักษร 13px คู่กับไอคอน **16px** ไม่ใช่ 20px (ข้อ 04 §6 เขียนไว้ผิด แก้แล้วในข้อ 3.1)
- **ไอคอนที่กดได้ต้องมีเป้า ≥ 24×24** ไอคอน 16px ต้องมี padding 4px เป็นขั้นต่ำ
- **`warning-500` ห้ามใช้เป็นสีไอคอนเด็ดขาด** ได้แค่ 1.66:1 ใช้ `warning-700` ขึ้นไป
- **ไอคอน 16px ที่สื่อความหมายควรใช้สีที่ได้ ≥ 4.5:1** ไม่ใช่ 3:1 ขั้นต่ำ เพราะ stroke 1.5px บางกว่าตัวอักษร
- **โหมดมืดใช้ขั้น 400 ทุกสี** สม่ำเสมอและผ่านทุกกรณี
- **สถานะต้องต่างกันที่รูปทรง** เตือน = **สามเหลี่ยม** ไม่ใช่วงกลมสีเหลือง เพราะทองกับเหลืองห่างกันแค่ 1.43:1
- **ปุ่มไอคอนล้วนได้แค่ 5 ตัว** ค้นหา · ปิด · ย้อนกลับ · เมนู · เพิ่มเติม — นอกนั้นต้องมีข้อความ
- **ไอคอนที่วาดเองต้องเป็น artboard 24 · live area 20 · stroke 2 · cap และ join แบบ round · ไม่มี fill**
- **ยังไม่มีไอคอนโดเมนไทย ให้ใช้ข้อความ** ห้ามหยิบไอคอน Lucide ที่ใกล้เคียงมาใช้แทน

## 💻 Developer Notes

- **ห้าม `import { X } from 'lucide-react'`** ใช้ `<Icon name="x" size={16} />` เท่านั้น — ตั้ง `no-restricted-imports` ให้ error ไม่ใช่ warn
- **`strokeWidth` ไม่มี prop ให้ override** เป็นการตัดสินใจของ API ไม่ใช่การละเลย
- **`IconSize` เป็น union type** ไม่ใช่ `number` — ค่านอกชุด compile ไม่ผ่าน
- **ไม่ส่ง `label` = ไอคอนตกแต่ง** ได้ `aria-hidden="true"` อัตโนมัติ · ส่ง `label` = ได้ `role="img"` + `aria-label`
- **`focusable="false"` บน SVG ทุกตัว** ป้องกัน SVG ติด tab order
- **`stroke="currentColor"`** ไอคอนรับสีจาก `color` ของ parent — ห้าม hardcode สีในไฟล์ SVG
- **ไอคอน 16px ที่กดได้ต้องมี `p-1`** ถ้า layout ไม่ให้ ใช้ pseudo-element ขยายพื้นที่กดตามตัวอย่างในข้อ 4
- **Tree-shaking:** `registry` ต้องเป็น static import map ไม่ใช่ dynamic `import()` ด้วยตัวแปร ไม่เช่นนั้น bundler จะรวมไอคอนทั้ง 1600 ตัว
- **ไอคอนที่วาดเองต้องมี `stroke-width="2"` และ `viewBox="0 0 24 24"`** เพื่อให้ wrapper คำนวณ scale ได้ถูก

## 🧠 Decision Rationale

### ทำไมไม่ใช้ stroke 2 ตามค่าเริ่มต้นของ Lucide
เพราะค่าเริ่มต้นนั้นถูกออกแบบมาสำหรับตาราง 24px และ**ไม่มีเจตนาให้ใช้กับทุกขนาด** เมื่อคำนวณสัดส่วนของเส้นต่อกล่องไอคอน stroke คงที่ให้ช่วงห่าง **3 เท่า** (12.5% ที่ 16px ถึง 4.17% ที่ 48px) ส่วนตารางที่ผูก stroke กับขนาดให้ช่วงห่าง **1.8 เท่า** — สม่ำเสมอกว่าอย่างวัดได้ ไม่ใช่เรื่องความรู้สึก

และปัญหาที่แท้จริงคือ ไอคอน 16px stroke 2 จะดู **หนักกว่าตัวอักษร `label` 13px ที่วางข้างกัน** ซึ่งกลับลำดับความสำคัญทางสายตา — ไอคอนควรสนับสนุนข้อความ ไม่ใช่แข่งกับข้อความ

### ทำไมไม่ทำสัดส่วนให้คงที่เป๊ะ
สัดส่วนคงที่ต้องใช้ stroke 1.33 ที่ 16px ซึ่งบนจอ 1× DPI จะถูกปัดเป็นเส้นบางกว่า 1px ทำให้ไอคอนซีดจนเสี่ยงไม่ผ่านเกณฑ์ 3:1 — และที่ 48px ต้องใช้ stroke 4 ซึ่งทำให้ไอคอนกลายเป็นภาพประกอบหนา ๆ เพราะที่ขนาดใหญ่ตาเริ่มอ่านไอคอนเป็นรูปทรงไม่ใช่สัญลักษณ์

ตารางนี้จึงเป็นการประนีประนอมที่ตั้งใจระหว่างความสม่ำเสมอทางสายตา ความสามารถในการ render และการผ่านเกณฑ์ contrast — และการเขียนตัวเลขสัดส่วนไว้ในเอกสารทำให้คนรุ่นถัดไปเห็นว่าเป็นการเลือกที่มีเหตุผล ไม่ใช่ค่าที่ตั้งลอย ๆ

### ทำไมบังคับด้วย API ไม่ใช่เอกสาร
เพราะการคัดลอกโค้ดจาก lucide.dev เป็นพฤติกรรมปกติและได้ `strokeWidth={2}` ทุกครั้ง กฎที่อยู่ในเอกสารเท่านั้นจะถูกละเมิดโดยไม่มีใครตั้งใจ

การให้ `size` เป็นตัวกำหนด stroke และ**ไม่มี prop ให้ override** ทำให้ผิดไม่ได้ และ `no-restricted-imports` ทำให้ทางลัดถูกปิดตั้งแต่ต้น — นี่คือความต่างระหว่าง design system ที่ถูกทำตามกับที่ถูกอ้างถึง

### ทำไมไอคอน 16px ควรใช้เกณฑ์ 4.5:1 แม้ข้อกำหนดคือ 3:1
เพราะ SC 1.4.11 ระบุอัตราส่วน contrast แต่**ไม่ได้คำนึงถึงความหนาของเส้น** ไอคอน 16px มี stroke 1.5px ซึ่งบางกว่าเส้นของตัวอักษรมาก และพื้นที่หมึกทั้งหมดเล็กกว่ามาก การอ่านเส้นบาง 1.5px ที่ 3:1 พอดีบนจอกลางแจ้ง — ซึ่งเป็นสถานการณ์จริงของ SME ที่ขายของหน้าร้าน — ยากกว่าการอ่านตัวอักษรที่ 3:1

การผ่านข้อกำหนดไม่ใช่เป้าหมายสุดท้าย เป้าหมายคือผู้ใช้เห็นไอคอนได้จริง

### ทำไมปุ่มไอคอนล้วนจำกัดแค่ 5 ตัว
เพราะไอคอนที่ผู้ใช้ตีความตรงกันจริงมีน้อยกว่าที่นักออกแบบคิด และผู้ใช้กลุ่มหลักของ SME.GO คือเจ้าของกิจการอายุ 40–60 ปีที่ไม่ได้คุ้นเคยดิจิทัล ซึ่งมีคลังสัญลักษณ์ในหัวเล็กกว่าผู้ใช้แอปทั่วไป

และเนื้อหาของแพลตฟอร์มนี้ — เอกสาร ภาษี การรับรอง แหล่งทุน — **ไม่มีสัญลักษณ์สากลอยู่แล้ว** ไอคอนสำหรับ "ใบกำกับภาษีอิเล็กทรอนิกส์" ไม่มีทางสื่อความหมายได้เองไม่ว่าจะวาดดีแค่ไหน

### ทำไมยังไม่วาดไอคอนโดเมนในชั้นนี้
เพราะชั้น Foundation ถูกกำหนดขอบเขตว่าไม่มี component และการวาดไอคอน 14 ตัวต้องรู้ก่อนว่าการรับรองและช่องทางชำระเงินไหน**ปรากฏจริง**ในผลิตภัณฑ์ ซึ่งเป็นข้อมูลที่ยังไม่มี การวาดตอนนี้เสี่ยงวาดไอคอนสำหรับ flow ที่ถูกตัดออกภายหลัง

แต่การ**เขียนสัญญาไว้** มีต้นทุนต่ำและป้องกันปัญหาที่แก้ยากที่สุด — ไอคอนที่วาดกระจัดกระจายโดยไม่มีข้อกำหนดจะมีน้ำหนักเส้นและตารางไม่ตรงกับ Lucide ซึ่งเห็นได้ทันทีเมื่อวางเรียงกันในแถวเดียว และแก้ทีหลังหมายถึงวาดใหม่ทั้งหมด

### ทำไมต้องเขียนเรื่องการจัดแนวกับอักษรไทย
เพราะอักษรไทยซ้อนสระและวรรณยุกต์เหนือพยัญชนะ ทำให้ส่วนที่ตาอ่านว่าเป็น "ตัวอักษร" อยู่ค่อนไปทางล่างของกล่องบรรทัด การจัดไอคอนให้อยู่กลางกล่องบรรทัดตามวิธีมาตรฐานจึงทำให้ไอคอนดูสูงกว่าตัวพยัญชนะ

ที่ขนาดเนื้อหาความต่างนี้เล็กจนไม่ต้องแก้ แต่ที่ขนาด display เห็นชัด — และเป็นสิ่งที่ไม่มีใน design system ภาษาละตินเลย จึงไม่มีใครคาดว่าต้องตรวจ
